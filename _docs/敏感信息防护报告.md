## 二、防护体系（三层）

### 1. 扫描工具 `tools/secret-scan.mjs`

```bash
node tools/secret-scan.mjs                    # 扫描源码
node tools/secret-scan.mjs --include-build    # 含构建产物
node tools/secret-scan.mjs --path apps/foo    # 限定目录
node tools/secret-scan.mjs --json             # JSON 输出（CI 消费）
node tools/secret-scan.mjs --strict           # info 级也阻断
```

- **15 条规则**分三级：`critical`（私钥、含凭据连接串、支付密钥、云厂商凭据、AI 服务密钥）
  / `high`（地图 Key、JWT 密钥、OIDC Secret、对象存储凭据）/ `info`（疑似凭据，人工确认）
- **占位符豁免**：`your_xxx` / `CHANGE_ME` / `${VAR}` 等自动跳过，降低误报
- **输出脱敏**：值只显示前 4 后 4 位，`snippet` 全文过脱敏

### 2. 忽略清单 `.secret-scan-ignore`

排除「已确认非本项目凭据」的误报源，每条都写明理由：第三方离线文档副本、
历史规划文档、扫描器自身。**把真实项目文件加进来等于关闭检查，请勿滥用。**

### 3. CI 门禁 `.github/workflows/secret-guard.yml`

三个检查：
1. 全仓静态扫描（源码 + 构建产物），critical/high 阻断
2. **`.env` 入库校验**：直接查 git 索引 —— 因为 `.gitignore` 对**已跟踪文件无效**，
   这是本仓库真实踩过的坑（9 个 `.env` 已入库但规则一直"存在"）
3. **构建产物入库校验**（排除 WordPress 核心的 `wp-includes/{js,css}/dist`）

## 三、关键认知（本次踩到并已解决的坑）

### 坑 1：`.gitignore` 对已跟踪文件无效
仓库 `.gitignore` 早有 `.env` / `.env.*` 规则，但 9 个环境文件仍在版本库里 ——
它们在规则生效**之前**就已 `git add`。**规则存在 ≠ 文件被忽略**，
必须 `git rm --cached` 摘除索引（工作区文件保留，操作可逆）。

### 坑 2：通配 `**/dist/` 会误伤 WordPress
WordPress 核心自带 `wp-includes/js/dist` 与 `wp-includes/css/dist`
（本仓库 354 个文件）。用 `**/dist/` 排除构建产物会把它们一起删掉、破坏站点。
已改为按实际产物路径精确列出。

### 坑 3：安全工具自身会成为泄露放大器
扫描器 `--json` 输出的 `snippet` 字段原样保留命中行，等于把密钥复制进报告；
该报告在一次 `git add -A` 中被扫进索引，**所幸被 GitHub 推送保护拦截**，
令牌未外泄。现已对所有输出强制脱敏。

### 坑 4：告警疲劳会让门禁失效
初版门禁报 critical 35 / high 60，绝大多数是 `postgres://...@localhost` 这类
开发默认值。全红 = 无人看。已引入分级：指向本地/docker/占位主机且口令无
「大小写+数字」随机特征的，降级为 info。**反向验证**：指向生产主机且为随机密钥
（`Kx9pQz2mVb7nR4tL@db.prod.internal`）仍判 critical，确认未放过真凭据。

### 坑 5：中文路径导致"是否入库"误判
`git ls-files` 默认转义非 ASCII 路径（`E\347\233\230...`），
导致中文文件名的文件被误判为"未跟踪"。应统一用 `git ls-files -z` 处理。

### 附带修复的 PII 加密缺陷

`sites/gexm-platform/packages/user-service/src/utils/encrypt.ts` 原实现：
```ts
Buffer.from(config.cryptoKey.padEnd(32, '0').slice(0, 32), 'utf-8')
```
若 `CRYPTO_KEY` 未配置或过短，密钥会静默退化成 **32 个 `'0'`**——
等于用一把人尽皆知的钥匙加密用户个人身份信息（PII）。
已改为：缺失/过短（<16 字符）时**直接抛错拒绝启动**，并用 SHA-256 派生定长密钥。

## 六、日常使用

**提交前自检**（可选，CI 会兜底）：
```bash
node tools/secret-scan.mjs
```

**新增密钥的正确姿势**：
1. 后端/边缘：环境变量注入（EdgeOne 控制台 / 服务器 env），前端永不接触
2. 前端：只能通过自家后端接口间接调用第三方服务
3. 模板：提交 `xxx.env.example`，键名保留、值写 `<请填写>`
4. 确认 `.gitignore` 覆盖，且**文件从未被跟踪**（`git ls-files | grep .env`）

**若密钥已入库**：先吊销密钥 → `git rm --cached` 摘索引 → 需要清历史时用
`git filter-repo`（本仓库此前已做过一次全量清洗，有可复用的 Runbook）。
