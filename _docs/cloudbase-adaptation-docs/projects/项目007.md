# 项目007 · CloudBase 适配方案

> 适配等级：**B · 后端可迁** ｜ 预估工作量：**3–4 天** ｜ 代码改动：**中等**

## 1. 现状诊断

| 维度 | 现状 |
|---|---|
| 技术栈 | FastAPI（9 处）+ Electron/Tauri/React Native 客户端 + SQLite（4 处）+ PostgreSQL（1 处） |
| 源文件规模 | 142 个源文件 |
| 当前数据层 | server/app/config.py 声明 PostgreSQL；SQLite 4 处（regen_static_content.py、seed_demo_ai_rebirth.py） |
| 认证方式 | 未检出独立认证模块 |
| 文件/存储 | 未见文件存储 |
| 后端形态 | FastAPI 服务 + 静态导出（scripts/export_static.py、makers/） |
| 已接入云服务 | **无** CloudBase 接入（makers/ 为 EdgeOne Makers 部署） |

FastAPI 后端 + 多端客户端（Electron / Tauri / React Native），
clients/ 下三个客户端共用 src/api/client.ts 的调用模式，说明**接口契约已经统一** —— 这有利于改造。

config.py 已声明 PostgreSQL，说明后端本来就是关系型。CloudBase 已支持 MySQL/PG，
因此**不需要改数据模型**，只需换连接目标。

## 2. CloudBase 能力映射

| 现有能力 | CloudBase 对应 | 迁移方式 |
|---|---|---|
| FastAPI 后端 | CloudBase 云托管 CloudRun | **不要迁云函数** —— FastAPI 是长驻服务，云函数冷启动会拖慢响应 |
| PostgreSQL | CloudBase PostgreSQL 实例 | 同构迁移，schema 与 SQL 基本不用改 |
| SQLite（4 处） | 云数据库 | seed/regen 脚本里的 SQLite 是本地工具，可保留；若运行时依赖则必须迁 |
| 静态导出（export_static.py） | CloudBase 静态托管 | 替代 EdgeOne Makers，或两者并存 |
| 三端客户端 api/client.ts | 保持 REST 不变 | 客户端零改动 —— 后端地址换即可 |

## 3. 接入点（需要改动的具体位置）

1. `server/app/config.py —— 数据库连接配置，改连 CloudBase PG`
2. `clients/manju_rn/src/api/client.ts、clients/manju_tauri/src/api/client.ts —— 客户端基地址配置`
3. `scripts/regen_static_content.py、scripts/seed_demo_ai_rebirth.py —— SQLite 使用点`
4. `makers/scripts/export_static.py —— 静态导出，对接静态托管`
5. `web/src/api.ts —— Web 端接口封装`

## 4. 改造步骤

### 步骤 1：后端上云托管（不是云函数）

FastAPI 属于长驻服务，用**云托管 CloudRun** 承载，保留完整 FastAPI 生态（连接池、中间件、后台任务）。
迁云函数会丢失这些能力且冷启动严重。

### 步骤 2：数据库换连接串

config.py 改 CloudBase PG 连接串即可，SQLAlchemy 模型无需改动。

### 步骤 3：客户端只改基地址

三个客户端共用同一套 api/client.ts 模式，**只改 baseURL** 即可完成对接。

### 步骤 4：静态资源可并行

export_static.py 产出的静态资源，可选迁静态托管；若 EdgeOne Makers 已稳定可不动。

## 5. 风险与注意

- **不要把 FastAPI 塞进云函数** —— 冷启动 + 无长连接，体验会明显劣化。云托管是正确的落点。
- SQLite 若只在 seed/regen 脚本里用（本地工具），无需迁移；若运行时依赖则必须迁，需先确认。
- 三端客户端（RN / Tauri / Electron）若已分发，改 baseURL 需考虑旧版本兼容。
- CloudBase PG 与本地 PG 版本/扩展可能不一致，迁移前核对扩展依赖（如 pgvector）。
