## 补充：Packages 可发布性修复（本环境已本地验证）

上一轮把 `shared/*` 改为「产出 dist 可消费」，但本次构建验证发现一个**发布阻断 bug**：
`shared/config/src/index.ts` 通过相对源码路径 `../../map/src/{types,config}` 引入了
`@afdk1991/shared-map` 的实现。这种跨包源码引用在发布后**无法解析**（发布包里只有自己的 `dist/`，
没有 `../map/src`），且 `tsc` 因 rootDir 约束直接报错 TS6059。

已修复（纯本地改动，已 `rm` 掉验证用的 dist，由 CI 重新产出）：
1. `shared/config/src/index.ts`：改为 `import ... from '@afdk1991/shared-map'`（包名导入）。
2. `shared/config/package.json`：新增 `"dependencies": { "@afdk1991/shared-map": "^1.0.0" }`，
   使发布后的 config 正确声明对 map 的依赖，消费方 `npm install` 会自动拉取 map。
3. `shared/config/tsconfig.build.json`：新增 `paths` 映射
   `"@afdk1991/shared-map": ["../map/dist/index.d.ts"]`，构建时从本地 map 的构建产物解析类型，
   无需从 registry 拉取未发布的 map。
4. `.github/workflows/publish-packages.yml`：原为并行 matrix `[config,http,map]`，改为
   **单 job 顺序步骤 map → http → config**，且用根安装的 `tsc` 直接构建（不跑 `npm install`，
   避免 install 阶段去拉取尚未发布的 map 依赖）。每个包发布前用 `npm view` 探测版本幂等跳过。

本地验证结果（构建后检查 `dist` 产物）：
- `shared/map/dist`、`shared/http/dist`、`shared/config/dist` 均正常产出 `index.js` + `index.d.ts`。
- `shared/config/dist/index.js` / `index.d.ts` 的导入目标已变为 `@afdk1991/shared-map`
  （不再是 `../../map`），即**发布后可在消费端正确解析**。
- `dist/` 已被根 `.gitignore` 的 `dist/` 规则忽略，不会误提交。
