## ⚠️ 关键定论（2026-10-08 深夜）：WorkBuddy GitHub 连接器对本仓库**只读**
- 用户要求"用已连接的 GitHub"推送。实测：连接器 MCP 能读（`get_me`/`get_file_contents` 正常），
  但**写入被拒**：`push_files`(Git Data API 建 tree) 与 `create_or_update_file`(Contents API PUT)
  均返回 `403 Resource not accessible by integration`。
- 根因：连接器底层是 **GitHub App / 集成令牌**，对 `afdk1991/manju` 仅有读权限、无 write 权限；
  不是本机配置问题，也不是令牌缺失——是 App 未在该仓库安装/未授权 write。
- 因此本机**四条写通道全死**：①SSH(无登记密钥) ②HTTPS git(无 token/credential helper)
  ③MCP push_files(403) ④MCP create_or_update_file(403)。
- 解锁写权限**只能由用户在 GitHub 账号侧操作**：给该连接器背后的 App 在 `afdk1991/manju`
  上安装并授权 contents:write；或在 WorkBuddy 重连 GitHub 连接器时授予 repo 写 scope；
  或仍走"登记 manju SSH 公钥 / 提供 PAT"任一口子。三者任一到位，我即可立即推送（bundle 已备好）。
- 本机为排查 TLS 吊销检查坑设的 `http.schannelCheckRevoke=false` 保留；`http.sslVerify` 已回退 true。
