## 第二轮（晚）：红果从 embed 升级为 direct + 真实浏览器验证

### 起因

上一轮留下的两个缺口：① 红果只能 iframe 嵌入，体验差；② iframe 实际渲染效果
**没能验证**（本机 Edge headless 输出 0 字节、提权也无效）。

### 关键突破链（四步，都靠实测而非猜测）

1. **`robots.txt` 泄露路由**：`Disallow: /player/ 两级路径`。
   上一轮按 `/play?series_id=`、`/player?series_id=` 等 **query 形式**探测，全 404，
   所以得出「无独立播放器页」的错误结论。实际是 **路径形式** `/player/<sid>/<ep>`。
2. **播放器页 SSR 里带真流**：字段 **`main_url`** → 签名 mp4（CDN `v*-hgweb.qznovelvod.com`）。
   ⚠️ 源站把 `/` 转义成 **`\u002F`**，必须先 `replace(/\\u002F/g,'/')` 再正则，否则一个字都抠不到。
3. **防盗链实测**（同一签名地址）：不带 Referer → 206；源站 Referer → 206；
   **本站 Referer → 403**。⇒ 浏览器直连必然 403，必须走 proxy。
   ⇒ 适配器标 `antiLeech:true`，下发 `proxied_first:true`，前端代理优先。
4. **类型判定陷阱**：字节系 VOD 地址**无扩展名**（`.../video/tos/.../?mime_type=video_mp4`），
   proxy 里只认 `.mp4` 后缀会把它们全拒了 → 补 `mime_type` 参数识别 + 响应 Content-Type 二次校验。

### 改了什么

- `_lib/ext_providers.js`：适配器接口扩展为
  `cdnSuffixes / antiLeech / buildPlayerUrl / buildEmbedUrl / extractStreams`；
  新增 `isCdnHost` / `authorizeMedia`（CDN 放行，SSRF 边界不放大）。
- `ext/play`：新增「优先走播放器页抠真流」步骤；支持 `ep`（集索引）与 `fresh=1`（跳缓存）；
  抠出的地址一律再过 `authorizeMedia`（第三方页面属不可信输入）。
- `ext/proxy`：改用 `authorizeMedia`；放宽类型判定；响应 Content-Type 二次校验。
- `ExternalPlayer.tsx`：新增 **`ready` 态**——数据就绪但被浏览器自动播放策略挡住时，
  显示「▶ 点击播放」而不是一直"正在缓冲"；按 `proxied_first` 调整尝试顺序。
- `test_ext_functions.mjs`：新增第 [5] 节端到端拉流断言。

### 首次部署后浏览器复验暴露两个真 bug（都已修）

`dpsli9bboujl` 部署后，浏览器里 `hasReady=0`：video 的 `src` 已指向本站 proxy，
但 `readyState=0`、`networkState=3 (NETWORK_NO_SOURCE)`，**网络面板里却没有任何错误**。

排除过程（值得复用）：
1. curl 直接打 proxy → 206 / video/mp4 / 0.7s，Range 也正确（0-1023 与 50000-51023
   各自返回对应 Content-Range，没有错误复用缓存）。
2. `network requests` → 请求确实发了、确实 206。
3. **隔离实验**：`eval` 里 `document.createElement('video')` 直接喂服务端给的 proxied 地址
   → `loadedmetadata`、`rs=4`、`ns=2`、`dur=120`、无 error。
   ⇒ **服务端没问题，是 React 组件的锅。**

**bug ①（🔴 关键）**：`attempts` 在组件体内计算，`buildAttempts` 每次渲染都返回
**新数组 + 新对象**；而挂载 `<video>` 的 effect 依赖了 `current` 这个对象引用
→ 每轮渲染 effect 都重跑 → 每次都执行 `v.src = …; v.load();` 把加载重置
→ 视频永远加载不完，且因为请求本身成功，**任何网络层都查不到错误**。
修复：`attempts` 改 `useMemo(…, [pb])`；effect 依赖改基础值 `[pb, sourceIdx]`（双保险）。

**bug ②（🔴 体验）**：数据就绪（`readyState=4`）但浏览器自动播放策略要求先有用户手势，
`playing` 事件永不到来 → 界面**一直停在「正在缓冲，请稍候…」**，用户以为卡死。
修复：新增 `ready` 态，监听 `canplay`/`loadeddata`，若「用户还没播过」则显示
「▶ 点击播放（N 秒）」入口；用 `startedRef` 区分「等首次播放」与「用户主动暂停」，
避免暂停时覆盖原生控制条。
