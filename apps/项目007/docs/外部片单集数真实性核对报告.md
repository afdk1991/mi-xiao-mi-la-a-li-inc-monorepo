# 外部片单「集数真实性」核对报告

- 核对时间：2026-10-08
- 范围：AI 剧 989 条 + 漫剧 1021 条 = **2010 条**
- 数据源：源站 `/detail?series_id=`（robots 允许路径）的 SSR 字段
- 明细：`reports/free-episodes-2026-10-06T16-13-01.json`

## 一、核对口径

单看「能不能播」不够，观众看到的是「全 227 集」，能看的是另一回事。所以用三条独立口径互相印证：

| 口径 | 字段 | 含义 |
|---|---|---|
| 标称集数 | 片单 `episodes` / `episodes_text` | 采集到的来源站标注 |
| 源站全集 | `episode_cnt` / `episode_total_cnt` + `vid_list.length` | 源站登记的全部影片 |
| **真实免费可播** | **`accessible_episode_cnt`** | 源站明示的可访问（免费）额度 |

判定规则：取 `accessible_episode_cnt` 与 `vid_list.length` 的较小值 —— 宁可少报，也不能把用户导向点不开的集。

## 二、结论

| 指标 | 结果 |
|---|---|
| 解析成功 | 1996 / 2010（失败 14 条，源站返回 404） |
| 标称 == 源站全集数 | 1950 / 1996（97.7%） |
| 标称 == 真实免费可播 | **0 / 1996（0%）** |
| **标称 > 真实可播（虚标）** | **1996 / 1996（100%）** |
| 真实可播集数分布 | **3 集 × 1996 部（100%）** |
| 虚标差值 | 中位 101 集，最小 4，最大 997 |

**一句话结论：标称数字本身没错（与源站全集一致率 97.7%），错在没有区分「全集」和「免费部分」。
源站免费放出的部分一律只有前 3 集，其余是付费内容。**

此前片单直接展示标称值，等于把用户骗进播放页 —— 这是虚假陈列，已修正。

## 三、附带查出并修复的 BUG：只能播第 1 集

根因不在数据，在接口：`ext/play` 把集索引硬填成 `0`，前端也从未传 `ep`。
而源站第 2 集起的 URL 是 `/player/<sid>/<vid>` —— **第二个参数是影片 ID，不是集序号**。
填 `0` 的结果就是任何剧都只能拿到第 1 集。

修复：从播放器页 SSR 抽剧集 vid 清单，按集取流，并把可选集数下发给前端。

## 六、边界与遗留

- 本次只核对「免费可播集数」，**不对付费内容做任何绕过**，也未代理付费片段。
- `accessible_episode_cnt` 是源站自报字段；已用 300 条逐集探测独立验证过一次（结果完全吻合），
  但源站若调整免费策略，需要重跑解析脚本刷新数据。
- 自有内容（8 部剧各 1 集）是素材量问题不是 BUG：`content/generated/demo_ai_rebirth` 只生成了 ep01 的帧，
  扩集属于内容生产，需要剧本/素材输入。
