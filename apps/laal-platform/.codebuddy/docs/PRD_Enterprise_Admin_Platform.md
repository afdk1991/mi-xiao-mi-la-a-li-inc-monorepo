# PRD：企业级通用后台管理系统

---

## 1. 产品概述

### 1.1 产品名称

`enterprise_admin_platform`（企业通用后台管理系统）

### 1.2 产品定位

一套面向中小型企业的**通用型后台管理系统**，提供开箱即用的用户管理、数据管理、文件管理、仪表盘等核心能力，可快速二次开发适配各行业场景。

### 1.3 核心价值

| 价值维度 | 描述 |
|---------|------|
| **效率** | 预置 CRUD、搜索、导出、仪表盘等通用模块，减少 60%+ 重复开发工作量 |
| **安全** | 完善的 RBAC 权限体系 + 操作日志审计，满足企业合规要求 |
| **体验** | 全响应式设计，桌面端/移动端无缝切换，统一设计语言 |
| **可扩展** | 模块化架构，支持快速接入新业务实体与 API |

### 1.4 目标用户

| 角色 | 典型场景 |
|------|---------|
| **系统管理员** | 管理用户账号、分配角色权限、配置系统参数 |
| **企业运营人员** | 日常数据录入与维护、批量操作、数据导出分析 |
| **业务管理人员** | 通过仪表盘查看业务数据概览、决策支持 |
| **开发人员** | 基于 API 文档进行二次开发与系统集成 |

## 2. 用户故事

### 2.1 认证与权限

> **As a** 系统管理员，**I want** 创建用户账号并分配不同角色权限，**so that** 不同岗位的员工只能访问其职责范围内的功能模块。

> **As a** 普通用户，**I want** 通过邮箱注册账号并在忘记密码时自助重置，**so that** 我不会因为忘记密码而无法工作。

### 2.2 数据管理

> **As a** 运营人员，**I want** 在列表页面查看、新增、编辑和删除业务数据，**so that** 我能高效维护系统中的数据记录。

> **As a** 运营人员，**I want** 对列表数据进行批量删除和批量状态变更，**so that** 我能一次性处理多条记录，节省操作时间。

### 2.3 搜索与筛选

> **As a** 运营人员，**I want** 通过关键词搜索和多条件高级筛选快速定位目标数据，**so that** 我不需要翻页逐条查找。

### 2.4 文件管理

> **As a** 运营人员，**I want** 上传文件并管理已上传的文件列表，**so that** 我能在系统中存储和引用相关资料。

### 2.5 数据导出

> **As a** 业务管理人员，**I want** 将列表数据导出为 PDF 或 Excel 文件，**so that** 我能离线查看或分享给未登录系统的同事。

### 2.6 仪表盘

> **As a** 业务管理人员，**I want** 在首页仪表盘查看关键业务指标的可视化图表，**so that** 我能快速掌握业务运营状况并做出决策。

### 2.7 系统设置与日志

> **As a** 系统管理员，**I want** 在系统设置中配置全局参数，**so that** 系统行为符合企业规范。

> **As a** 系统管理员，**I want** 查看操作日志，了解谁在什么时间做了什么操作，**so that** 出现问题时可以追溯排查。

### 2.10 API 文档

> **As a** 开发人员，**I want** 查看系统提供的 API 接口文档，**so that** 我能快速对接后端接口进行二次开发。

### 4.4 响应式适配策略

| 断点 | 宽度范围 | 适配策略 |
|------|---------|---------|
| **Desktop** | ≥1024px | 侧边栏常驻(240px)，内容区多列布局，表格完整展示 |
| **Tablet** | 768px–1023px | 侧边栏可折叠为图标栏(72px)，内容区双列→单列，表格保留 |
| **Mobile** | <768px | 侧边栏隐藏(抽屉式弹出)，内容区全宽单列，表格→卡片列表 |

**关键适配规则：**
- 表格在移动端转为**卡片列表**形式，每条记录一张卡片
- 表单在移动端统一**单列布局**
- KPI 卡片从 4 列 → 2 列 → 1 列
- 图表容器使用响应式容器，自动调整尺寸
- 导航在移动端使用**底部 Tab Bar**或**抽屉菜单**

### 4.5 设计规范

#### 4.5.1 色彩体系

| 用途 | 色值 | 说明 |
|------|------|------|
| 主色 (Primary) | `#1976D2` | 品牌蓝，用于主要按钮、链接、选中态 |
| 次色 (Secondary) | `#DC004E` | 强调色，用于危险操作 |
| 成功 (Success) | `#2E7D32` | 绿色，成功状态/提示 |
| 警告 (Warning) | `#ED6C02` | 橙色，警告提示 |
| 错误 (Error) | `#D32F2F` | 红色，错误状态/必填标记 |
| 背景色 | `#F5F5F5` | 页面背景 |
| 卡片背景 | `#FFFFFF` | 内容卡片背景 |
| 主文字 | `#212121` | 正文 |
| 次文字 | `#757575` | 辅助说明文字 |
| 边框 | `#E0E0E0` | 分割线/边框 |

#### 4.5.2 字体规范

| 层级 | 字号 | 字重 | 用途 |
|------|------|------|------|
| H1 | 28px | 700 | 页面主标题 |
| H2 | 22px | 600 | 区域标题 |
| H3 | 18px | 600 | 卡片标题 |
| Body | 14px | 400 | 正文/表格内容 |
| Caption | 12px | 400 | 辅助说明/标签 |

字体族：`'Inter', 'PingFang SC', 'Microsoft YaHei', sans-serif`

#### 4.5.3 间距规范

采用 **8px 基准网格**：

| Token | 值 | 用途 |
|-------|-----|------|
| xs | 4px | 紧凑间距（图标与文字） |
| sm | 8px | 组件内部间距 |
| md | 16px | 组件间标准间距 |
| lg | 24px | 区域间距 |
| xl | 32px | 大区块间距 |
| xxl | 48px | 页面级间距 |

#### 4.5.4 组件规范

- **圆角**：卡片 8px，按钮 6px，输入框 4px
- **阴影**：卡片 `0 2px 8px rgba(0,0,0,0.08)`，悬浮 `0 4px 16px rgba(0,0,0,0.12)`
- **按钮**：主按钮(填充色)、次按钮(描边)、文字按钮(无背景)
- **表格**：行高 48px，表头背景 `#FAFAFA`，斑马纹可选

## 5. 待确认问题

|---|------|------|------|
| 1 | **业务数据实体**：通用 CRUD 的"数据"具体指什么业务实体？（用户/订单/商品/自定义？） | 影响数据库设计与 CRUD 模板 | 建议：MVP 以"用户管理"作为示例 CRUD 实体，其他实体后续按模板扩展 |

| 3 | **邮件服务**：密码重置需要发邮件，使用哪种邮件服务（SMTP/第三方API）？ | 影响 P1 密码重置功能 | 建议：使用 Nodemailer + SMTP，预留 SendMail/Mailgun 接口 |

| 5 | **数据量级**：预期单表数据量级（千级/万级/百万级）？ | 影响分页策略与导出方案 | 建议：MVP 采用 OFFSET 分页，大数据量后续改为游标分页 |
| 6 | **多租户需求**：系统是否需要支持多租户隔离？ | 影响数据库架构设计 | 建议：MVP 单租户，预留多租户扩展方案 |
| 7 | **API 认证方式**：API 文档是否对外开放？是否需要 API Key 认证？ | 影响 API 文档模块设计 | 建议：Swagger UI 需登录后访问 |
| 8 | **国际化需求**：是否需要多语言支持？优先支持哪些语言？ | 影响 P2 国际化功能排期 | 建议：MVP 仅中文，代码预留 i18n 架构 |
| 9 | **浏览器兼容**：需要兼容到哪些浏览器及版本？ | 影响前端技术选型与 polyfill | 建议：Chrome 90+, Firefox 88+, Safari 14+, Edge 90+ |
| 10 | **数据可视化库**：图表使用哪个库（Recharts/ECharts/AntV）？ | 影响前端依赖与开发效率 | 建议：Recharts（轻量、React 原生），复杂场景用 ECharts |

## 附录：技术栈建议

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端框架 | Vite + React 18 + TypeScript | 快速构建、类型安全 |

| 图表 | Recharts | React 原生图表库 |
| 表单 | React Hook Form + Zod | 类型安全的表单校验 |
| 后端框架 | Node.js + Express + TypeScript | 与前端同语言，类型共享 |
| ORM | Prisma | 类型安全、迁移管理 |

| API 文档 | Swagger (swagger-jsdoc + swagger-ui-express) | 自动生成 OpenAPI 文档 |
| 部署 | Docker + Docker Compose | 容器化部署 |
