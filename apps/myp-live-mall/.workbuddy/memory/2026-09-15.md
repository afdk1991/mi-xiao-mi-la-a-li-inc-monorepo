### 踩坑与根因（重要，后续复用）

- **宿主端口被占**：3306=mixmlaal-mysql、8080=mixmlaal-wp-gateway-go、8081=mixmlaal-wp-service-java。
  报错 `failed to set up container networking ... Bind for 0.0.0.0:3306 failed: port is already allocated`。
  → 改用 13306/18080/18081。**Compose 对 `ports` 是追加合并不是替换，override 无法解决，必须写独立编排文件。**
- **全站 404 根因**：CLI 下 `wp_install()` 缺少 `HTTP_HOST`，`wp_guess_url()` 把 siteurl 写成
  `http:///var/www/html`（容器内 curl 200，宿主访问全 404）。
  → 安装后必须 `update_option('siteurl'/'home', 'http://localhost:PORT')`。
- **Docker daemon 无法跨 PowerShell 调用存活**：后台任务结束时进程树被清理。
  → 必须把「启动引擎 + compose + 安装 + 冒烟」放进**同一个长驻后台任务**，末尾 `Start-Sleep` 保持。
  WMI/Start-Process 启动 Docker Desktop 会被安全策略拦截或随会话清理。
- **PowerShell 脚本解析失败坑**：双引号字符串内写 `\"` 会导致字符串提前终止、整段脚本 parse 失败且不生成日志。
  PowerShell 转义应用 `` `" ``。排查时"日志没生成"=解析错误，不是运行错误。

### 服务生命周期（重要）

预览服务**依赖 Docker Desktop 运行**，而 daemon 会随维持它的后台任务结束被进程树清理。
任务到期后实测：daemon DOWN、站点不可达。
所有服务均为 `restart: always`，**只要 Docker Desktop 重新运行，容器会自动恢复**，
siteurl 等配置已持久化在 db_data 卷里，无需重装。

自助恢复命令（用户侧）：
```
docker desktop start
# 容器自愈后访问 http://localhost:18080
# 停止：docker compose -p myp006 down
```
