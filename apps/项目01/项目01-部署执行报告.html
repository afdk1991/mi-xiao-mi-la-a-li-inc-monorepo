二、核心架构决策：后端身份分裂已消除

2.1 改造前（问题）

  • Nginx 把所有 /api/ 代理到 127.0.0.1:3001，即 Node 版 02-后端微服务集群/mixmlaal-backend。
  • 但记忆与实际代码确认：合并后的真实后端是 python-fastapi（FastAPI + SQLAlchemy + JWT/bcrypt，/api/products 等真实数据）。
  • python-fastapi 未被任何部署配置引用 → 线上 API 与代码库不一致。
  • ecosystem.config.cjs 中 unified-api-gateway 占用 :8000，与主后端端口冲突。

2.2 改造后（全部指向 python-fastapi:8000）

部署机制改造内容状态
PM2新增 mixmlaal-python-backend（uvicorn app.main:app --port 8000）；原 Node mixmlaal-backend 由 Python 取代；unified-api-gateway 退役（注释保留）完成
Nginxnginx-mixmlaal.conf 3 处 /api/ 代理 :3001 → :8000（web-vue-pc / page-builder / web-h5-mobile）完成
Docker原仓库缺失 Dockerfile（Docker 路径不可用）→ 新增 python-fastapi/Dockerfile + .dockerignore + 根 docker-compose.yml；start-docker.sh 重写为 docker compose up完成
Render原 render.yaml 缺 build/start 命令 → 重写为 runtime: python、rootDir: python-fastapi、buildCommand: pip install、startCommand: uvicorn完成
为什么不再分裂：四条机制现在指向同一个后端进程（python-fastapi:8000）。机制保留是为了部署灵活性，不再是「同一流量被四套配置各说各话」。

五、生产机执行清单（沙箱无 SSH，需你在 laal.top 执行）

1. 准备密钥
export JWT_SECRET=$(python -c "import secrets;print(secrets.token_urlsafe(48))")
（务必持久化，重启后令牌失效；生产环境未设置时后端会拒绝启动）

2. 启动后端（三选一）
• PM2：pm2 start ecosystem.config.cjs --only mixmlaal-python-backend --env production && pm2 save
• Docker：export JWT_SECRET=... && docker compose up -d --build
• 直启：cd python-fastapi && uvicorn app.main:app --host 0.0.0.0 --port 8000

3. Nginx
部署 deploy/nginx-mixmlaal.conf，nginx -s reload；确认 /api/ → 127.0.0.1:8000

4. 前端 API 对接（关键）
前端已上线 EdgeOne，但其 /api/ 请求需指向后端域名。需在前端构建配置中设置 API 基址为 https://api.laal.top/api（或用 Nginx 反代），否则前端加载正常但数据接口不通。

5. 验证
curl https://api.laal.top/health → 期望 {"status":"healthy","database":"connected"}
