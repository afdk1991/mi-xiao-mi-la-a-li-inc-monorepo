## 沙盒坑（重要，可复用）

- 本机 `next build` 在 WorkBuddy Windows 沙盒**无法直接跑通**：托管 Node 二进制自带 safe-delete shim。
  - 现象1：cleanup `.next` 时调用 trash，因中文路径 `F:\新建文件夹` 被转成 POSIX `/f/新建文件夹` 导致 trash 拒绝 → `SAFE_DELETE_FAIL_CLOSED`。
  - 现象2：`recursiveDelete` 触发批量删除守卫 `CODEBUDDY_SAFE_DELETE_BULK_GUARD`（>50 文件需交互确认）→ `BULK_CONFIRM_REQUIRED`。shim 在 trash 失败时不回退真实删除。
- 结论：此类项目直接走云端部署 + 线上 URL 验证即可，别耗在本地 build。
- 部署前若需清理 `.next`，用 `rm -rf` 走无沙箱提权（escalation）可真正删除。
