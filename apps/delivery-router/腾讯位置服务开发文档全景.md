## 一、总览：能力矩阵

腾讯位置服务（LBS）面向 **Web 服务端、Web 前端、Android、iOS、小程序、Flutter、鸿蒙（HarmonyNEXT）** 七大端，提供 **地图、搜索、地址、路线、定位、轨迹、大数据** 七大类能力。

| 大类        | 代表能力                         | 主要形态                      |
| --------- | ---------------------------- | ------------------------- |
| 地图        | 底图、个性化样式、可视化、室内地图、瓦片         | JS API GL / 各端 SDK / WMTS |
| 搜索与地址     | 地点检索、POI详情、逆/地址解析、行政区划       | WebService API（服务端）       |
| 路线与导航     | 驾车/步行/骑行/公交/货车路线、距离矩阵、ETA    | WebService API + 各端导航 SDK |
| 定位        | 浏览器/IP 定位、智能硬件定位、RTK 厘米级     | WebService API + 各端定位 SDK |
| 轨迹云 / 地点云 | 轨迹上传查询、自有 POI 管理             | WebService API            |
| 大数据       | 数据魔方、人群热力、文旅客情、迁徙态势          | 控制台产品（非 API 广场）           |
| AI / 大模型  | MCP Server、Agent Skills、智能问答 | 大模型接入                     |

### 接入三步（最关键的坑都在这里）

1. **注册开发者** → 控制台（<https://lbs.qq.com/console）完善信息（企业认证配额显著高于个人）。>
2. **创建应用 & 申请 Key**：应用管理 → 我的应用 → 创建应用 → 添加 Key。
   - ⚠️ **务必勾选「WebServiceAPI」权限**（小程序 SDK、MCP、服务端调用都依赖它）。
   - Key 为 32 位字符串，各产品**通用**（同一 Key 可用于地图 SDK、JS API、WebService API）。
3. **分配配额**：配额管理 → 账户额度 → **一键分配**（把地点搜索、路线规划、逆地址解析等接口的额度分给该 Key）。
   - ⚠️ 不分配额度，调用会直接报错。

### 坐标系说明（与你项目强相关）

- 内地、港澳地区：**GCJ-02（火星坐标）**；台湾省：**WGS-84**。
- 你项目 `src/mapservice.ts` 中腾讯/高德走 GCJ-02、OSM 走 WGS-84 的设定与官方一致，无需改坐标转换即可对齐。
- 当传入三方经纬度时务必注意坐标系，避免偏移。

## 二、地图服务 API（WebService API · 33 个接口）

**基础信息**

- Base URL：`https://apis.map.qq.com/ws/`
- 协议：HTTPS/HTTP，**GET** 为主，返回 JSON / JSONP
- 鉴权：`key` 为**必填参数**（所有接口均需）
- 通用响应：`{ status, message, request_id, result }`，`status=0` 为正常
- 文档总入口：`https://lbs.qq.com/webservice_v1/`

## 十、与你项目（商品采集 / 配送定位）的集成建议

你的 `src/mapservice.ts` 已封装 `amap / tencent / osm` 三套服务，腾讯走 `apis.map.qq.com/ws/geocoder/v1` 与 `direction/v1/driving`，坐标系 GCJ-02。可基于本全景图**按需补齐**：

| 场景                  | 推荐接口                                             | 当前状态                                                                               |
| ------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 地址 → 坐标（批量导入）       | `geocoder/v1/?address=`                          | ✅ 已封装 `geocode()`（`geocode.ts`）                                                    |
| 坐标 → 送达地址（打印配送单/点选） | `geocoder/v1/?location=`                         | ✅ 已新增 `reverseGeocode()`（`geocode.ts`）                                             |
| 多目的地最优路径（TSP 前置）    | `distance/v1/matrix`                             | ✅ 已封装 `distanceMatrix()`（`routing.ts`）；路线面板「道路网排序」勾选后经 `buildRoute({roadNetwork:true})` 生效（默认关闭，避免无谓消耗配额） |
| 货车/快递配送路线           | `direction/v1/trucking`                          | ✅ 已封装 `getTruckRoute()`（`routing.ts`）+ 路线面板「货车模式」开关与货车参数（车型/长宽高重/车牌/策略）；高级付费需商务开通，未开通自动走兜底 |
| 可达范围圈选              | `distance/v1/isochrone`                          | ✅ 封装 `getIsochrone()`（`routing.ts`）+ **UI**：路线面板「起点可达圈」输入分钟数生成，地图按 `routeMode` 绘制多边形；腾讯真实街区面（青色实线），高德/OSM 圆形近似（`approx=true`，橙色虚线） |
| 起点吸附纠偏              | `direction/v1/{mode}` 的 `from_poi`              | ✅ 已支持：`getSegmentRoute(..., { fromPoi })`（腾讯生效）                                     |
| 步行 / 骑行 / 驾车多方式算路   | `direction/v1/{walking\|bicycling\|driving}`     | ✅ 封装 + **UI**：路线面板「出行」下拉（驾车/步行/骑行），持久化于 `delivery.routeOptions`；腾讯换 endpoint、OSRM 自动换 `foot`/`bicycle` 剖面；**高德仅驾车，其余交 OSRM**（不再拿驾车结果冒充） |
| IP 定位（初始化城市）        | `location/v1/ip`                                 | ✅ 封装 `locateByIp()`（`geocode.ts`）+ **UI**：起点弹窗「📍 用我的城市（IP 定位）」；高德走 `amap.ts` 网关（`v3/ip` / `AMap.CitySearch`） |
| 第三方坐标批量转换          | `coord/v1/translate`                             | ✅ 封装 `translateCoords()`（`geocode.ts`）+ **UI**：导入对话框「坐标来源」下拉（GCJ-02/WGS-84/百度/搜狗/图吧），导入时自动校正；腾讯真实转换；高德走 `amapConvertCoords`；OSM 原样返回 |
| 客户地址真实性校验           | 地址真实性分析 / 异常错误分析                                 | ⚪ 可选（官方未公开独立 Endpoint，需企业版/商务开通）                                                  |

### 新增能力的降级约定（与既有风格一致）

所有新增接口均遵循「主服务失败 → 降级 → 绝不中断」：

- `getIsochrone`：腾讯无 Key / 请求失败 / 轮廓解析失败 → 返回圆形近似（`approx=true`），UI 仍可展示范围。
- `translateCoords`：任一环节失败 → **原样返回该批坐标**，绝不丢点。
- `locateByIp`：OSM 无此能力 → `null`；调用方应静默处理。
- `getSegmentRoute({ mode })`：高德仅驾车（JS API 限制），步行/骑行自动走 OSRM 剖面。

> 切换地图服务时清空旧路线（坐标系变化，旧几何无效）——你项目已有此逻辑，保持一致。

## 十一、快速上手（Quick Start）

```bash
# 1) 验证 Key：地点搜索（返回 JSON 即成功）
https://apis.map.qq.com/ws/place/v1/search?keyword=火锅&boundary=region(成都,0)&key=YOUR_KEY

# 2) 逆地址解析（坐标 → 地址，到家场景精确到楼栋）
curl "https://apis.map.qq.com/ws/geocoder/v1/?location=39.984,116.307&get_poi=1&poi_options=policy=2&key=YOUR_KEY"

# 3) 地址解析（地址 → 坐标）
curl "https://apis.map.qq.com/ws/geocoder/v1/?address=北京市海淀区中关村大街1号&region=北京&key=YOUR_KEY"

# 4) 驾车路线规划
curl "https://apis.map.qq.com/ws/direction/v1/driving?from=39.984154,116.307490&to=39.980092,116.309198&key=YOUR_KEY"

# 5) 距离矩阵（多起点×多终点）
curl "https://apis.map.qq.com/ws/distance/v1/matrix?mode=driving&from=39.98,116.30&to=39.99,116.32;39.97,116.34&key=YOUR_KEY"
```

> 调用前确认：① Key 已创建且勾选 WebServiceAPI；② 已**一键分配配额**；③ 参数做 URL 编码。
