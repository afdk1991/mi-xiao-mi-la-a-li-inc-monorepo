# 加密算法、认证方式与操作系统技术参考文档

## 一、常用加密算法

### 1. 对称加密（加解密同密钥）

| 算法 | 安全等级 | 适用场景 | 推荐说明 |
|------|---------|---------|---------|
| AES-256 | 极高 | 文件加密、数据库、传输加密、磁盘加密 | 行业标准，通用首选，全平台兼容 |
| AES-128 | 高 | 移动端、嵌入式、轻量化业务 | 性能均衡，物联网设备常用 |
| 3DES | 低（淘汰） | 老旧遗留系统兼容 | 新项目禁止使用，存在安全缺陷 |
| DES | 极低（废弃） | 无现代业务场景 | 极易暴力破解，仅历史兼容 |
| SM4（国密） | 极高 | 政务、金融、等保合规项目 | 国内涉密/等保要求强制选用 |

### 2. 非对称加密（公钥加密、私钥解密）

| 算法 | 安全等级 | 适用场景 | 推荐说明 |
|------|---------|---------|---------|
| RSA 2048 | 中高 | 证书、HTTPS、数字签名 | 通用，但密钥长，性能一般 |
| RSA 4096 | 极高 | 金融、高安全后台 | 加密速度慢，仅签名/密钥交换 |
| ECC P-256 | 极高 | 手机、芯片、物联网、小程序 | 同等安全下密钥短小，性能远优于 RSA |
| SM2（国密） | 极高 | 政务、国企、等保三级及以上 | 国产商用密码，替代 RSA/ECC |

### 3. 哈希摘要（不可逆校验）

| 算法 | 安全等级 | 适用场景 | 推荐说明 |
|------|---------|---------|---------|
| MD5 | 极低（作废） | 仅老旧文件校验，禁止存密码 | 极易碰撞，无安全价值 |
| SHA-1 | 极低（作废） | 旧版证书兼容，新项目禁用 | 已出现碰撞攻击 |
| SHA-256 | 高 | 文件校验、数据摘要、密码加盐哈希 | 互联网通用标准 |
| SHA-512 | 极高 | 高安全后台、日志校验 | 抗暴力破解能力更强 |
| SM3（国密） | 极高 | 国内合规系统，替代 SHA256 | 国密配套哈希算法 |

### 4. 通用协议加密

| 协议 | 安全等级 | 场景 | 推荐 |
|------|---------|------|------|
| TLS 1.3 | 极高 | HTTPS、API 接口、小程序、APP | 全网统一新标准，必须启用 |
| TLS 1.2 | 中高 | 老旧设备兼容，不单独主推 | 仅作为兼容兜底 |
| SSL 3.0/TLS1.0/1.1 | 极低 | 全部禁用，高危漏洞 | 直接下线 |
| SSH 2.0 | 高 | 服务器远程登录、文件传输 | 运维标准加密协议 |
| IPsec | 高 | 内网 VPN、跨机房专线加密 | 企业内网组网加密 |

## 二、常见认证方式

| 认证类型 | 安全等级 | 适用场景 | 说明与推荐 |
|---------|---------|---------|---------|
| 账号 + 静态密码 | 低 | 基础后台、内网低权限系统 | 单独使用不安全，必须搭配二次认证；建议加盐哈希存储密码 |
| PIN 码 | 中 | 手机、硬件设备、本地锁屏 | 仅限本地短码，不能独立对外认证 |
| 短信验证码 | 中 | 登录、支付、找回密码 | 存在短信劫持风险，高安全场景不能单用 |
| 邮箱验证码 | 中 | 注册、账号找回 | 比短信稳定，不适合金融级核心操作 |
| TOTP 动态令牌（谷歌验证） | 高 | 后台管理员、支付、高权限账号 | 推荐作为二次认证标配，离线可用 |
| 硬件 U 盾 / USB 数字证书 | 极高 | 银行、政务、涉密系统、等保三级 | 私钥隔离硬件，无法窃取，最高安全认证 |
| 生物认证（指纹/人脸） | 中高 | 手机解锁、APP 快捷登录 | 仅做本地/前端验证，后端需搭配令牌，不可单独做主认证 |
| OAuth2.0 / 第三方登录 | 中 | 网站、小程序快捷登录（微信/支付宝） | 仅授权身份，不承载核心权限 |
| JWT Token | 高 | 前后端分离、微服务、API 接口 | 无状态认证，适合分布式系统，需搭配 HTTPS |
| Session 会话 | 中 | 传统单体 Web 系统 | 服务端存储，分布式需共享存储 |
| 设备指纹 + IP 白名单 | 高 | 后台运维、内部管理平台 | 限制登录设备与网段，辅助防护 |
| 国密证书认证 | 极高 | 政务、军工、金融合规平台 | 配套 SM2/SM3/SM4 整套国密体系 |

| | 非对称 | ECC P256 / SM2 | RSA1024 及以下 |

## 五、落地安全规范

1. **等保三级及以上系统**：全套采用国密算法（SM2+SM3+SM4）、国密证书认证、国产操作系统
2. **互联网对外接口**：统一 TLS1.3 + AES256 + SHA256，接口鉴权使用 JWT
3. **管理员账号**：强制开启双因素认证（密码 + TOTP / 硬件证书）
4. **老旧组件下线**：废弃加密算法、老旧传输协议定期下线，操作系统持续更新安全补丁
