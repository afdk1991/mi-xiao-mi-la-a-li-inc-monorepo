## 一、项目概述

### 1.1 项目目的

Gexm 是一个面向中小型电商运营团队的全平台电商系统，旨在提供从商品管理、订单交易、支付结算到会员营销的完整数字化运营能力。系统采用"一套代码、多端覆盖"策略，通过 Monorepo 架构统一管理后端服务、移动应用、小程序、PC 管理后台和桌面客户端，降低多端维护成本。

### 1.2 项目目标

| 目标维度 | 描述 | 量化指标 |
|----------|------|----------|
| **业务目标** | 为电商运营团队提供一站式交易与管理平台 | 支持日活用户 5000+，订单并发 500 QPS |
| **技术目标** | 建立可扩展、高可用的电商技术底座 | 单进程 QPS ≥ 150，可用性 ≥ 99.5% |
| **用户体验目标** | 多端一致、流畅的购物体验 | H5 首屏 LCP < 2.5s，API P95 < 500ms |
| **架构目标** | 从单体平滑演进到微服务架构 | 支持灰度发布、全链路追踪、服务独立部署 |
| **质量目标** | 建立完善的测试与监控体系 | 核心模块测试覆盖率 ≥ 70%，ESLint 零错误 |

### 1.3 目标用户

| 用户角色 | 使用端 | 核心场景 | 规模预估 |
|----------|--------|----------|----------|
| **C 端消费者** | H5 / 小程序 / App | 浏览商品、下单支付、查看订单、参与营销活动 | 5000 DAU |
| **店铺运营人员** | PC 管理后台 / 桌面端 | 商品管理、订单处理、营销配置、数据查看 | 10-50 人 |
| **系统管理员** | PC 管理后台 | 用户管理、权限分配、审计日志、系统配置 | 2-5 人 |
| **财务人员** | PC 管理后台 | 对账管理、退款审核、财务报表 | 2-5 人 |
| **客服人员** | PC 管理后台 / App 内嵌管理 | 在线客服、订单查询、用户咨询 | 5-10 人 |

### 1.4 业务价值主张

1. **全端覆盖**：一套代码覆盖 H5、4 种小程序、原生 App、PC、桌面端，降低多端开发与维护成本 60%+
2. **交易闭环**：从商品浏览到支付完成、物流跟踪、售后退款的完整交易链路
3. **营销引擎**：内置优惠券、秒杀、会员积分、签到等营销工具，无需第三方插件
4. **数据驱动**：实时监控、审计日志、财务对账，支撑运营决策
5. **平滑演进**：双写迁移、灰度发布机制，支持从 SQLite 单体到 PostgreSQL 微服务的零停机演进
6. **AI 赋能**：集成 LangChain + MCP 的 AI Agent，提供智能客服与订单查询能力

### 2.2 详细功能需求

#### 2.2.1 认证与授权模块（AUTH）

**FR-AUTH-01：用户注册**
- 支持用户名/邮箱/手机号三种注册方式
- 密码强度校验：≥8 位，含大小写字母+数字+特殊字符
- 注册后自动登录并签发 JWT（Access 2h + Refresh 7d）
- 验证码校验：邮箱注册需验证码，手机注册需短信验证码
- **验收标准**：重复用户名注册返回 409；密码弱返回 400；成功返回 200 + token

**FR-AUTH-02：用户登录**
- 支持用户名/邮箱/手机号 + 密码登录
- 登录失败 5 次锁定 15 分钟（`login_attempts` 表记录）
- 登录成功后重置失败计数
- 返回 `access_token` + `refresh_token` + 用户基本信息
- **验收标准**：错误密码返回 401；锁定期间返回 423；成功返回 200 + token

**FR-AUTH-03：令牌刷新**
- Refresh Token 有效期 7 天，存储于数据库
- 刷新时签发新 Access Token，可选签发新 Refresh Token
- 旧 Refresh Token 失效（单次使用）
- **验收标准**：无效 Refresh Token 返回 401；成功返回 200 + 新 token

**FR-AUTH-04：OAuth 第三方登录**
- 支持 7 个提供商：微信（开放平台/公众号/小程序）、QQ、微博、支付宝、Google、Facebook、Twitter
- OAuth 2.0 授权码流程，State 参数防 CSRF
- 首次登录自动创建/绑定用户账号
- 支持已有账号绑定第三方
- **验收标准**：授权码无效返回 400；绑定冲突返回 409；成功返回 200 + token

**FR-AUTH-05：个人资料管理**
- 查看/编辑昵称、头像、手机号、邮箱
- 修改密码（需验证旧密码）
- 敏感操作（改手机号/邮箱）需二次验证（验证码 + sensitive_verify_tokens）
- PII 数据（手机号、身份证）AES-256 加密存储
- **验收标准**：未验证返回 403；验证码错误返回 400；成功返回 200

#### 2.2.2 商品中心模块（PROD）

**FR-PROD-01：商品浏览（公开）**
- 商品列表：分页、按分类筛选、按价格/销量/创建时间排序
- 商品详情：基本信息、SKU 列表、图片、描述、评价摘要
- 商品搜索：关键词搜索 + 搜索历史记录
- **验收标准**：分页参数校验；无数据返回空数组（非 404）；响应 P95 < 200ms

**FR-PROD-02：商品管理（管理员）**
- 创建商品：名称、描述、分类、图片（multer 上传）、SKU 配置
- 编辑商品：全字段可编辑，变更需审计日志
- 上下架：状态切换，下架商品前台不可见
- 库存管理：按 SKU 扣减，`stock_logs` 记录变更
- **验收标准**：非管理员返回 403；库存不足返回 400；成功返回 201/200

**FR-PROD-03：分类管理**
- 分类树形结构（支持二级分类）
- 分类 CRUD（管理员）
- 分类商品关联
- **验收标准**：删除有商品的分类返回 409

#### 2.2.3 订单交易模块（ORDR）

**FR-ORDR-01：订单预览**
- 入参：商品 SKU ID + 数量列表、可选优惠券 ID、可选地址 ID
- 出参：商品明细、金额计算（商品金额、运费、优惠、积分抵扣、实付）
- 库存校验（不扣减）
- **验收标准**：库存不足返回 400 标识具体商品；优惠券不可用返回 400

**FR-ORDR-02：订单创建**
- 事务操作：创建订单 → 扣减库存 → 核销优惠券 → 清空购物车（如来自购物车）
- 订单号生成：时间戳 + 随机数，唯一性保证
- 订单超时：未支付订单 30 分钟自动取消（cronService 定时任务）
- 异步通知：订单创建后发布队列消息，触发通知/统计/日志
- **验收标准**：并发不超卖（分布式锁保障）；订单创建响应 < 500ms；异步任务失败不影响主流程

**FR-ORDR-03：订单状态机**

```
待支付 (pending) 
  ├── 支付成功 → 待发货 (paid)
  │     ├── 发货 → 待收货 (shipped)
  │     │     ├── 确认收货 → 已完成 (completed)
  │     │     └── 超时未收货 → 自动完成
  │     └── 退款申请 → 退款审核中 (refunding)
  │           ├── 审核通过 → 已退款 (refunded)
  │           └── 审核拒绝 → 恢复待发货
  ├── 超时未支付 → 已取消 (cancelled)
  └── 用户主动取消 → 已取消 (cancelled)
```

- 状态流转需权限校验（用户只能取消自己的订单）
- 每次状态变更记录审计日志
- **验收标准**：非法状态转换返回 400；非本人订单返回 403

**FR-ORDR-04：订单查询**
- 用户查询自己的订单（按状态筛选、分页）
- 管理员查询所有订单
- 订单详情：商品、金额、地址、物流、支付信息
- **验收标准**：越权访问返回 403

**FR-ORDR-05：物流跟踪**
- 管理员录入物流单号
- 用户查看物流状态
- 物流信息变更触发通知
- **验收标准**：物流单号格式校验

#### 2.2.4 支付结算模块（PAY）

**FR-PAY-01：支付发起**
- 支持微信支付、支付宝、余额支付、模拟支付（开发环境）
- 支付前校验订单状态（必须为 pending）
- 生成支付参数返回客户端
- **验收标准**：订单状态非 pending 返回 400

**FR-PAY-02：支付回调**
- 接收支付网关异步通知
- 验签（IP 白名单 + 签名校验）
- 幂等处理（同一支付单多次回调只处理一次）
- 更新订单状态为 paid
- 发布支付成功队列消息
- **验收标准**：验签失败返回 400；重复回调返回 200 但不重复处理

**FR-PAY-03：对账管理**
- 每日自动对账（订单金额 vs 支付金额）
- 差异记录到 `reconciliation_records` 表
- 差异告警通知
- **验收标准**：差异率 < 0.01%

#### 2.2.5 营销活动模块（MKT）

**FR-MKT-01：优惠券**
- 优惠券类型：满减、折扣、无门槛
- 优惠券领取：用户领取，限量控制
- 优惠券使用：订单核销，使用规则校验
- 优惠券管理：管理员创建/停用
- **验收标准**：超量领取返回 400；过期券不可用返回 400

**FR-MKT-02：秒杀活动**
- 活动创建：管理员配置活动商品、价格、库存、时间
- 秒杀下单：分布式锁防超卖，限购控制
- 活动状态查询：未开始/进行中/已结束
- **验收标准**：并发不超卖；活动未开始返回 400

**FR-MKT-03：会员积分**
- 签到得积分（每日签到，连续签到奖励）
- 购物得积分（按实付金额比例）
- 积分抵扣（下单时按比例抵扣）
- 积分记录查询
- **验收标准**：积分不足抵扣返回 400

#### 2.2.6 管理后台模块（ADMIN）

**FR-ADMIN-01：仪表盘**
- 今日数据：订单数、GMV、新用户数、活跃用户数
- 趋势图表：近 7/30 天订单趋势
- 热销商品 TOP 10
- 待处理事项：待发货订单、退款申请
- **验收标准**：数据延迟 < 5 分钟；图表加载 < 1s

**FR-ADMIN-02：RBAC 权限管理**
- 角色 CRUD：4 个系统角色（super_admin、product_admin、order_admin、finance_admin）
- 权限管理：23 项权限 × 11 个模块
- 用户角色分配：一个用户可拥有多个角色
- 权限校验：中间件 `permission.ts` 逐接口校验
- **验收标准**：无权限访问返回 403

**FR-ADMIN-03：审计日志**
- 记录所有写操作（创建/更新/删除）
- 记录操作前后数据快照
- 支持按操作人、时间、模块查询
- **验收标准**：审计日志不可篡改

#### 2.2.7 AI 助手模块（AGENT）

**FR-AGENT-01：智能客服**
- 基于 LangChain ReAct 框架（Thought → Action → Observation）
- 支持 3 个技能：订单查询、商品搜索、用户信息查询
- 通过 MCP 协议暴露工具能力
- 最大 5 轮对话迭代
- **验收标准**：响应时间 < 5s；无效问题返回友好提示

#### 2.2.8 社交互动模块（SOCIAL）

**FR-SOCIAL-01：在线客服 IM**
- WebSocket 实时通信（socket.io）
- 会话管理：创建、列表、已读标记
- 消息类型：文本、图片、商品卡片
- **验收标准**：消息送达 < 1s；离线消息存储

**FR-SOCIAL-02：商品评价**
- 订单完成后可评价
- 评分 + 文字 + 图片
- 评价审核（管理员可隐藏）
- **验收标准**：未购买不可评价

### 2.3 接口规范

- **协议**：HTTPS（生产强制）
- **格式**：JSON，UTF-8 编码
- **认证**：Bearer Token（`Authorization: Bearer <token>`）
- **CSRF**：双重提交 Cookie（`X-CSRF-Token` 头）
- **响应信封**：`{ code: number, message: string, data: any }`
- **错误码**：0(成功)、1002(未认证)、1003(无权限)、1004(不存在)、1005(参数错误)、1007(Token过期)、5000(服务器错误)
- **分页**：`?page=1&pageSize=20`，响应 `{ list, total, page, pageSize }`
- **限流**：全局 100 req/min/IP，登录 5 req/min/IP

## 十、维护与支持

### 10.1 维护级别

| 级别 | 响应时间 | 解决时间 | 示例 |
|------|----------|----------|------|
| P0 紧急 | 15 分钟 | 2 小时 | 生产宕机、支付故障、数据丢失 |
| P1 高 | 1 小时 | 8 小时 | 核心功能异常、性能严重下降 |
| P2 中 | 4 小时 | 24 小时 | 非核心功能异常、UI 问题 |
| P3 低 | 24 小时 | 7 天 | 优化建议、文档更新 |

### 10.2 监控与告警

| 监控项 | 告警阈值 | 工具 | 动作 |
|--------|----------|------|------|
| 服务可用性 | 连续 3 次健康检查失败 | Prometheus + 告警规则 | 自动重启 + 通知 |
| 错误率 | > 5%（5 分钟窗口） | monitoring.ts | 告警通知 |
| 内存使用 | > 512MB | monitoring.ts | 告警 + 检查泄漏 |
| 响应时间 P95 | > 1000ms | APM | 告警 + 性能分析 |
| 数据库连接 | 连接池满 | PostgreSQL 日志 | 告警 + 扩容 |
| Redis 连接 | 连接失败 | cacheService | 降级内存缓存 |
| 消息队列积压 | > 1000 条 | queueService stats | 告警 + 扩容消费者 |
| 磁盘空间 | > 80% | node-exporter | 告警 + 清理 |

### 10.3 备份策略

| 数据 | 备份频率 | 保留期 | 存储位置 |
|------|----------|--------|----------|
| SQLite 数据库 | 每日 1 次（凌晨 3 点） | 30 天 | 本地 + 异地 |
| PostgreSQL | 每日全量 + 每小时增量 | 30 天 | 本地 + 异地 |
| Redis | RDB 每 5 分钟 + AOF | 7 天 | 本地 |
| 上传文件 | 实时同步 | 永久 | 本地 + 对象存储 |
| 日志文件 | 不备份（按轮转保留） | 30 天 | 本地 |
| 配置文件 | Git 版本控制 | 永久 | Git 仓库 |

### 10.4 故障恢复

| 故障类型 | 恢复步骤 | RTO |
|----------|----------|-----|
| 应用崩溃 | PM2 自动重启 | < 10s |
| 服务器宕机 | 切换备用服务器 | < 5min |
| 数据库故障 | 切换至备用数据库 | < 10min |
| Redis 故障 | 降级至内存缓存 | < 1s（自动） |
| 消息队列故障 | 降级至内存队列 | < 1s（自动） |
| 数据损坏 | 从备份恢复 | < 30min |

### 10.5 版本发布

| 发布类型 | 频率 | 流程 | 回滚策略 |
|----------|------|------|----------|

| 常规发布 | 每 2 周 | develop → PR → 审查 → main → 部署 | 回滚上一稳定版本 |
