# Gexm 全平台项目综合梳理文档

## 一、项目架构概述

### 1.1 项目定位

Gexm 是一个基于 **monorepo** 架构的全平台电商系统，采用跨平台开发策略，实现了移动端（iOS/Android）、小程序（微信/支付宝/百度/头条）、H5 网页和桌面端（Windows/macOS/Linux）的统一代码复用。

### 1.2 技术栈

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| **前端框架** | Vue | 3.4.21 | 核心框架 |
| **状态管理** | Pinia | 2.1.7 | Vue3 官方状态管理 |
| **跨平台** | uni-app | 3.0.0-alpha-50009 | 多端统一开发框架 |
| **构建工具** | Vite | 5.2.8 | 前端构建工具 |
| **样式** | Sass | 1.71.1 | CSS 预处理器 |
| **后端框架** | Express | 4.18.3 | Node.js Web 框架 |
| **数据库** | better-sqlite3 | 9.4.3 | SQLite 数据库驱动 |
| **认证** | jsonwebtoken | 9.0.2 | JWT 令牌认证 |
| **安全** | helmet | 7.1.0 | 安全中间件 |
| **实时通信** | socket.io | 4.8.3 | WebSocket 通信 |
| **桌面端** | Electron | 28.2.0 | 桌面应用框架 |

### 1.3 Monorepo 结构

```
f:\gexm/
├── packages/
│   ├── server/          # 后端服务
│   ├── app/             # 前端 uni-app 应用
│   ├── desktop/         # Electron 桌面应用
│   └── shared/          # 共享代码库
├── docs/                # 项目文档
├── scripts/             # 辅助脚本
└── config files         # 根级别配置
```

### 1.4 架构特点

- **高代码复用率**：通过 uni-app 实现 80%+ 代码跨平台复用
- **统一数据模型**：共享代码库提供类型定义和工具函数
- **前后端分离**：RESTful API 架构，前端通过代理访问后端
- **渐进式缓存策略**：通过 Vite 的 optimizeDeps 和 SSR 配置优化构建

## 二、项目结构详细分析

### 2.1 后端服务 (packages/server)

#### 2.1.1 目录结构

```
src/
├── config/              # 配置管理
├── constants/           # 常量定义
├── controllers/         # 控制器层（25个控制器）
├── middleware/          # 中间件（8个安全相关中间件）
├── models/              # 数据模型（27个模型）
├── routes/              # 路由定义（23个路由模块）
├── services/            # 业务服务层（1个服务）
├── utils/               # 工具函数
├── app.js               # Express 应用入口
├── server.js            # HTTP 服务器入口
└── websocket.js         # WebSocket 服务
```

#### 2.1.2 核心组件

| 组件 | 文件 | 功能说明 |
|------|------|----------|
| **应用配置** | `config/index.js` | JWT、安全、数据库、上传等配置 |
| **数据库初始化** | `models/index.js` | 表创建、索引、默认数据初始化 |
| **安全中间件** | `middleware/security.js` | XSS过滤、CSRF保护、安全头设置 |
| **认证中间件** | `middleware/auth.js` | JWT 令牌验证 |
| **订单服务** | `services/orderService.js` | 订单业务逻辑（事务处理） |
| **WebSocket** | `websocket.js` | 实时消息推送 |

#### 2.1.3 安全架构

后端采用多层安全防护：

1. **输入层**：XSS 过滤、输入长度限制、递归清理
2. **传输层**：HTTPS 强制跳转、安全头设置（HSTS、CSP、X-Frame-Options）
3. **认证层**：JWT + 刷新令牌机制
4. **防护层**：CSRF 令牌验证、速率限制
5. **数据层**：参数化查询（防 SQL 注入）

### 4.1 ESLint 检查结果

**执行命令**: `npm run lint`

#### 4.1.1 问题统计

| 问题类型 | 数量 | 严重程度 | 说明 |
|----------|------|----------|------|
| **格式化错误** | ~11,000+ | Error | Prettier 格式不符（分号问题） |
| **未使用变量** | ~60+ | Warning | 声明但未使用的变量/导入 |
| **ESLint/Prettier 冲突** | 1 | Warning | `order-list.vue` 循环修复检测 |
| **全局变量未定义** | 3 | Error | `plus` 对象（uni-app 原生 API） |

#### 4.1.2 主要问题分析

1. **Prettier 配置冲突**：前端文件存在大量分号差异，需运行 `npm run lint:fix` 自动修复
2. **全局变量声明缺失**：`platform-config.js` 中使用了 `plus` 对象但未在 ESLint 配置中声明
3. **未使用的导入**：多个页面存在 `onMounted` 导入但未使用

#### 4.1.3 代码规范合规性

| 规范项 | 状态 | 说明 |
|--------|------|------|
| **JavaScript ES6+** | ✅ 符合 | 使用 `const/let`、箭头函数、解构赋值 |
| **Vue Composition API** | ✅ 符合 | 统一使用 `<script setup>` 语法 |
| **RESTful API 命名** | ✅ 符合 | 接口路径语义清晰 |
| **错误处理** | ⚠️ 部分符合 | 大部分有 try-catch，但缺少统一错误码定义 |
| **代码注释** | ❌ 不符合 | 部分函数缺少 JSDoc 注释 |

### 4.2 测试覆盖率

**执行命令**: `npm run test --workspace=@gexm/server`

#### 4.2.1 测试结果

| 测试文件 | 结果 | 通过/失败 |
|----------|------|----------|
| `auth.test.js` | ✅ PASS | 通过 |
| `chat.test.js` | ✅ PASS | 通过 |
| `security.test.js` | ❌ FAIL | 3 个失败 |

#### 4.2.2 测试失败分析

1. **CSRF 中间件测试失败**（3个用例）
   - 原因：`csrfProtectionMiddleware` 在测试环境下直接跳过（`NODE_ENV === 'test'`），导致验证逻辑无法测试
   - 影响：无法验证 CSRF 防护的正确性

2. **支付测试数据库错误**
   - 原因：`flash_sale_items` 表的 `limit_per_user` 列重复添加
   - 影响：测试无法正常执行
