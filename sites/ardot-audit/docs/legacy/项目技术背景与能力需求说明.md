# 项目技术背景与能力需求说明

> **用途**：本文档是「开发代码助手（AI Coding Assistant）」的项目级 Standing Context。任何生成代码、设计方案、评审或排障动作，均须以此文档为边界约束。改动前先确认是否与下方「选型约束」和「非功能指标」冲突。

---

## 0. 一句话定位

面向**互联网/SaaS 高交互 B 端系统**，同时服务**金融业务、大型传统企业、高合规场景**；系统须内建**数据智能（LLM / RAG / 数据分析）**能力，并具备**实时处理与高并发网关**的基础设施底座，在**快速迭代**的同时保障**稳定、事务一致与技术治理**。

---

## 1. 业务领域

| 维度 | 特征 | 对技术的要求 |
|---|---|---|
| 互联网/SaaS B 端 | 多租户、高交互、频繁需求变更 | 前后端分离、模块化、可灰度、快速交付 |
| 金融业务 | 资金账务、强一致、不可丢失 | 分布式事务、对账、幂等、审计留痕 |
| 大型传统企业 | 组织复杂、系统林立、流程长 | 微服务治理、集成能力、稳定优先 |
| 高合规场景 | 等保/行业监管、数据出境限制 | 加密、脱敏、权限分级、不可篡改审计 |

**编码提示**：金融业务相关模块默认按「强一致 + 可审计」实现；合规字段默认脱敏；多租户数据默认行级隔离。

---

## 2. 技术方向

- **数据智能**：以数据分析驱动业务决策，近实时与离线分析并存。
- **大模型应用**：LLM 用于问答、生成、摘要、决策辅助；需支持私有化/多云模型切换。
- **RAG 检索增强生成**：基于企业知识的检索+生成，须引用溯源、防幻觉。
- **基础设施实时化**：网关低延迟、实时通信（推送/双向）、高并发吞吐。

---

## 3. 研发诉求

| 诉求 | 含义 | 落地手段 |
|---|---|---|
| 快速迭代 | 缩短需求到上线周期 | BFF 聚合、模块化单体、CI/CD、组件化 |
| 开发效率 | 减少重复与样板 | TS 统一语言、代码生成、AI 辅助、约定优于配置 |
| 系统稳定 | 故障可控、可恢复 | 限流熔断、多活、混沌演练、可观测性 |
| 事务一致性 | 资金/订单不丢不错 | 分布式事务（Seata）、幂等、对账 |
| 技术治理 | 多团队不失控 | 服务注册发现、统一网关、Mesh、规范卡点 |

---

## 4. 核心能力（系统必须具备）

1. **AI 与数据分析能力**：LLM/RAG 服务化、向量检索、批量与流式分析、决策看板。
2. **极致吞吐与高并发**：网关层高 QPS 低延迟、实时通道稳定、资源弹性。

---

## 5. 系统架构设计目标

| # | 目标 | 说明 |
|---|---|---|
| G1 | 多语言融合、边界清晰 | Go 网关/实时、Java 业务合规、Python 智能层、TS 展现层，以 gRPC/事件总线解耦 |
| G2 | 合规优先 | 合规校验作为强制关卡，贯穿输入脱敏与输出审计 |
| G3 | 智能内建 | LLM/RAG/分析以「能力服务」形态被业务调用，非外挂 |
| G4 | 弹性与高可用 | 容器化 + K8s 多活，核心链路跨 AZ |
| G5 | 可演进 | 模块化单体起步，规模驱动再拆微服务，避免过度设计 |
| G6 | 可观测 | 指标/日志/链路三位一体，问题可定位 |

## 6. 关键技术选型约束

| 层 | 技术 | 约束/理由 |
|---|---|---|
| 展现层 | React / Vue 3 + TypeScript | 多端统一；BFF 用 NestJS 做接口编排与鉴权中继 |
| 接入层 | **Go**（Gin/Echo） | 高性能网关、gRPC、WebSocket/SSE；限流/熔断/幂等在前置 |
| 业务核心 | **Java**（Spring Boot/Cloud） | 强事务、复杂业务、治理；Seata 分布式事务、Sentinel、Nacos |
| 智能层 | **Python**（FastAPI） | LLM 编排、LangChain/LlamaIndex、pgvector、Celery 异步分析 |
| 关系库 | PostgreSQL（业务）/ Oracle（合规账务） | 事务型主存储；合规账务优先 Oracle |
| 分析库 | ClickHouse | 海量聚合分析 |
| 缓存 | Redis | 热点缓存、会话、限流计数 |
| 消息 | RocketMQ / Kafka | 事件驱动、削峰、最终一致 |
| 向量/文档 | pgvector + 对象存储 | RAG 知识库与文档 |
| 基础设施 | Docker + K8s + Istio | 统一编排、Mesh 流量治理、mTLS |
| 可观测 | Prometheus + Grafana + Jaeger | 指标/日志/链路 |
| 交付 | GitOps（ArgoCD）+ 流水线 | 自动化构建/测试/安全扫描/发布 |
| 合规 | 等保2.0、国密(SM4)可选、OAuth2/OIDC、RBAC+ABAC | 加密、脱敏、审计、租户隔离 |
| 信创 | 国产 CPU/OS/DB（鲲鹏/麒麟/达梦） | 政企场景按需适配 |

**禁止项**：非必要不引入新语言栈；跨语言调用必须走 gRPC 或消息，禁止直接库依赖耦合；敏感数据禁止落明文日志。

## 7. 重点保障的非功能性指标（NFR）

| 类别 | 指标 | 目标（基线，按业务校准） |
|---|---|---|
| 性能 | 网关 P99 延迟 | ≤ 50ms（内部 gRPC） |
| 吞吐 | 网关单机 QPS | 万级起步，可水平扩展 |
| 实时 | 推送端到端延迟 | ≤ 200ms |
| 可用性 | 系统 SLA | ≥ 99.95%，核心多活 |
| 一致性 | 资金类 | 强一致 + 对账，零资损 |
| 一致性 | 分析类 | 最终一致，可接受秒级延迟 |
| 安全 | 传输/存储加密 | TLS1.3 + 静态加密，敏感字段脱敏 |
| 审计 | 操作留痕 | 100% 覆盖，不可篡改，独立存储 |
| 合规 | 等保/监管 | 满足对应等级与数据出境约束 |
| 可观测 | 链路覆盖 | 核心链路 100% 埋点，MTTR < 15min |
| 多租户 | 隔离 | 行级隔离，租户间无越权 |
| 迭代 | 交付频次 | 支持每日多次安全发布 |
| 扩展 | 容量 | 无单点，弹性伸缩 |

## 8. 代码助手工作守则（生成代码前必读）

1. **先对齐架构目标**：新模块归属哪一层？用哪门语言？是否符合第 6 节选型约束。
2. **合规默认开启**：涉及用户/资金/敏感数据，默认加脱敏、权限校验、审计日志。
3. **事务边界清晰**：Java 侧资金逻辑用分布式事务+幂等；禁止在事务内调用外部慢服务。
4. **AI 调用受控**：LLM 输入先脱敏，输出过合规校验与引用溯源；模型网关支持私有化切换。
5. **接口契约优先**：跨服务用 gRPC/OpenAPI 定义契约，先定义后实现。
6. **可测试、可观测**：关键路径加日志与指标；提交含单测与必要集成测试。
7. **不过度设计**：优先模块化单体与简单方案，规模证据出现再演进。
8. **安全扫描**：不硬编码密钥，密钥走 KMS；依赖须经漏洞扫描。
