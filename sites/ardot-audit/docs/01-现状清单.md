### 5.2 自定义表：`wp_saas_agg_logs`（本次新增）

由插件 activation hook 通过 `dbDelta()` 创建，遵循 WordPress 数据表规范（动态前缀 + `get_charset_collate()` + 版本存 option）。

```sql
CREATE TABLE `wp_saas_agg_logs` (
  `id`          bigint unsigned    NOT NULL AUTO_INCREMENT,
  `created_at`  datetime           NOT NULL,
  `user_id`     bigint unsigned    NOT NULL DEFAULT '0',
  `tenant_id`   varchar(64)        NOT NULL DEFAULT '',
  `provider_id` varchar(64)        NOT NULL DEFAULT '',
  `endpoint`    varchar(255)       NOT NULL DEFAULT '',
  `http_status` smallint unsigned  NOT NULL DEFAULT '0',
  `duration_ms` int unsigned       NOT NULL DEFAULT '0',
  `cache_hit`   tinyint(1)         NOT NULL DEFAULT '0',
  `result`      varchar(16)        NOT NULL DEFAULT 'ok',
  `message`     text,
  PRIMARY KEY (`id`),
  KEY `tenant_id`   (`tenant_id`),
  KEY `provider_id` (`provider_id`),
  KEY `created_at`  (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_520_ci;
```

设计要点：
- **索引**按三个真实查询维度建立（按租户、按数据源、按时间），与后台日志筛选一致；
- 表结构版本号存在 `wp_options` 的 `saas_aggregator_db_version`（当前 `1.0.0`），升级时由 `needs_upgrade()` 触发 `dbDelta()`；
- **不落库敏感信息**：`log()` 内部做字段裁剪与脱敏，密钥与响应正文绝不入库；
- 所有读写走 `$wpdb->prepare()`。

| 层 | 现状 |
| --- | --- |
| 操作系统 | Windows 11 + WSL2 Ubuntu 22.04 |
| PHP（本地开发） | 8.1.2（WSL 内），含 mysqli / mysqlnd / gd / zip / curl / sodium / intl 之外的必要扩展 |
| 数据库 | MySQL 8.0.46（Docker，WSL 内） |
| 本地开发地址 | `http://127.0.0.1:8090`（服务器运行在 WSL 内） |
| 容器化部署 | nginx + php-fpm 8.2 + mysql 8.0 + redis 7（见 `docker/`） |

> **为什么开发服务器跑在 WSL 内**：MySQL 在 WSL 的 Docker 里。若 PHP 在 Windows 侧运行，每次数据库连接都要穿过 Windows↔WSL 的端口中继，该通道在高频短连接下会成簇丢包（表现为 `Error while reading greeting packet` / `MySQL server has gone away`）。把 PHP 放进 WSL 后，PHP 与数据库同处一个网络命名空间，实测从「7 连败 4 连成」变为 **15/15 全绿**。
