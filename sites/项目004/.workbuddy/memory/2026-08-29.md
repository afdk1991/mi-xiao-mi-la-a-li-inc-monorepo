## 本次踩到的坑（高价值，务必记住）

### 1. PHP 内置服务器 router.php 的路径分隔符（阻塞安装的根因）
Windows 下 `realpath()` 返回反斜杠，与 `__DIR__` 拼接的正斜杠做 `strpos()` 前缀比较**恒为 false**，
导致所有真实文件被误判不存在、全部转发给 index.php → install.php 无限 302 自重定向。
**修复**：加 `wp004_normalize_path()` 统一转 `/` 再比较。

### 2. Windows ↔ WSL 的 localhostRelay 在高频短连接下成簇丢包
MySQL 跑在 WSL 的 Docker 里，PHP 跑在 Windows 侧时，每次连接都要穿过端口转发。
症状：`Error while reading greeting packet` / `(HY000/2006) MySQL server has gone away`，12 次请求失败 7 次。
**根治**：PHP 也移到 WSL 内（`scripts/serve-wsl.sh`），与 MySQL 同网络命名空间 → 15/15 全绿。

### 3. `db-error.php` 的两个必踩陷阱
该文件由 `wpdb::db_connect()` 内部 `require`，此时：
- `$wpdb` 全局**尚未赋值**，必须用 `$this`（`$this instanceof wpdb`）取实例
- 数据库已挂，调用 `esc_html()` 等会访问 DB 的 WP 函数会**递归 fatal**，只能用 `htmlspecialchars()`
- `error_log()` 此时 `WP_DEBUG_LOG` 未生效，直接 `file_put_contents` 落盘

### 4. 未安装 WordPress 时 `wp-load.php` 会 `die()` 且退出码为 0
`wp-settings.php` 里的 `wp_not_installed()` 走 `wp_redirect()` + `die()`，`die()` 无参数 → **exit code 0**。
所以 `php -r 'require wp-load.php; exit(is_blog_installed()?0:1)'` 判定"是否已安装"**永远返回已安装**。
**正确做法**：走 HTTP —— 未安装时访问 `/` 会 302 到 `/wp-admin/install.php`，看 `%{redirect_url}` 是否为空。

### 5. 插件模块挂在 `plugins_loaded` 闭包上，同请求内激活会失效
`activate_plugin()` 是在请求中途调用的，那时 `plugins_loaded` 早已触发，闭包再也不会执行
→ REST 路由一条都没注册。
**修复**：改具名函数 `saas_agg_bootstrap()` + `did_action('plugins_loaded')` 判断，已触发则立即引导，
并用 `static $bootstrapped` 防重复。

### 6. 别用 sed 硬抠美化过的 JSON
`verify-core.php --json` 输出带缩进（`"verdict": "PASS"`，冒号后有空格），
固定模式 `sed -n 's/.*"verdict":"\([^"]*\)".*/\1/p'` 匹配不到，把 PASS 误判成失败。
**正确做法**：用 PHP 解析后输出成 `key=value` 行再 sed。

### 7. Docker 构建：`pecl install imagick` 需要访问 github.com
受限网络下必然失败（`Failed to connect to github.com port 443`，需拉 PHP-Parser）。
已移除，只保留 `pecl install redis`（来自 pecl.php.net，可达）。GD 兜底缩略图。

- **核心零改动的三层保证**：开发层（只用官方扩展机制）/ 校验层（对账官方 checksums）/ **部署层（容器里核心来自镜像层，宿主机根本改不了）**

### 探测结论（实测，非推断）
- **网关鉴权**：`gateway-go` 未鉴权返回 `401 + 缺少 Authorization 或 X-Tenant-Id 头`；
  插件 `class-api-client.php` 正好传这两个头，注释亦写「网关不校验令牌值」→ 契约本来就对得上。
- **数据源契约**：`ai-python` OpenAPI（智能层 AI 服务 v0.2.0）路径为 `/health`、`/api/ai/llm`、
  `/api/ai/rag`、`/api/ai/index`、`/api/ai/analyze`、`/api/ai/tasks/{id}`、`/api/analytics/dashboard`、
  `/api/compliance/status`，参数统一为 header `X-Tenant-Id`（非必填），无安全方案。
  插件默认路径中 `/api/ai/rag`、`/api/analytics/dashboard`、`/api/compliance/status` 三者完全命中。
- **`mixmlaal-wp-portal:8088`** 确实是另一个 WordPress（Apache 2.4.59 + PHP 8.2.21 + wp-json）。
- **网关路径反推**：`/api/gateway/status` 200、`/api/orders` 200、`/api/products` **404**、
  `/api/ai/rag` GET 返回 405（需 POST）、`/api/analytics/dashboard` 200、`/api/compliance/status` 200。

### 揪出的两个真实契约缺陷（只有真跑才暴露）
1. **电商源地址指错服务**：`/api/products` 在 **node-api:3001** 而非 gateway-go:8080。
   原实现让 6 个源共用一个默认 `base_url`（网关），必然取不到数。
2. **Node 层响应包装与 Python 层不同**：
   Python 层 `{"tenant":...,"items":[...]}`；Node 层 `{"code":200,"msg":"成功","data":{"products":[...]}}`
   ——`data` 里再套一层**具名集合**。原 `normalize_response()` 把 `data` 当列表遍历，
   遍历到的是 `{"products":[...]}` 整块，归一化后 title/value 全空。

## 追加：许可证与商用合规性分析（新增 `docs/05-许可证与商用合规分析.md`）

### 结论
**有条件商用**。① 自建站点对外提供商业服务：可以，无附加义务（GPLv2 不限制"运行"，无 AGPL 网络条款）。
② 打包出售/交付主题插件：可以，但须完整履行 GPLv2 义务。③ Redis 作托管服务售卖 / Akismet 免费 Key 跑商业站：不可以。

### 实测证据（全部实测，非推断）
- 核心完整性 PASS：改动 0 / 缺失 0 / 非法新增 0 → GPL 声明完整保留
- active_plugins 只有 saas-aggregator；Akismet 未激活且无 key
- 版本：MySQL 8.0.46(GPL) / Redis 7.4.11 / nginx 1.27.5 / PHP 8.2.33
- 加密混淆扫描（ionCube/eval base64/gzinflate/300+ base64）：命中 0

### 三个真问题
1. **Redis 7.4.11 = RSALv2/SSPLv1 双许可（非 OSI、非 FSF）**——Redis 自 7.4 起从 BSD-3 改许可。
   但边界要划准：RSALv2 只禁"商业化/作托管服务提供给他人"+"移除声明"，**自用缓存不属于**。
   且本项目**根本没用 Redis**（wp-config 无配置、无 object-cache.php、代码零引用），是空转容器 → 当前风险 0。
   替代：valkey/valkey:8-alpine（BSD-3，drop-in，100% 协议兼容）或 redis:7.2-alpine 或删除该服务。
2. **Akismet 代码 GPLv2+ 但服务受 ToS 约束**——"Free keys are for personal, non-commercial sites only"。
   未激活 → 风险 0。激活后商业站用免费 Key = 合同违约（Key 被停，非诉讼）。
3. **ZibStyle 命名**——已核查代码是原创（grep `zibll`/`_zib_` 命中的全是注释文案，无 Zibll 实现代码；
   自有函数统一 `zibstyle_*` 前缀），**不侵犯著作权**；但名称近似商业品牌 Zibll（子比）+ 描述明示
   "参考 Zibll 设计风格" → 商标淡化/搭便车风险，**与 GPL 无关，GPL 不授予商标权**。
   建议更名 + 清除约 9 处 "Zibll" 表述。

### 其他发现
- **GPLv2 无明示专利授权**（GPLv3 §11 才有）。WordPress 是 GPLv2-or-later，
  可行使 "or later" 按 **GPLv3** 接收以获专利授权 → 建议 LICENSE 写明。成本为零。
- **HTTP 调用外部微服务不构成衍生作品**（GPLv2 §2 mere aggregation）→ 下游微服务许可证不影响本项目 GPL 合规。
- getID3 是**多重许可**（GPLv1/2/3、LGPLv3、MPL2），选 GPLv2 即对齐。
- twentytwentyfive 字体是 **OFL 1.1**，商用+Web 嵌入允许，但**仓库未随附 OFL 文本**（分发时需补）。
- 自研插件/主题文件头已正确声明 GPL-2.0-or-later，但**目录内无独立 LICENSE 全文**（仅分发时需要）。

### 踩坑
- 用 Windows 侧 PHP + `WP004_ABSPATH=/var/www/html` 跑 `verify-core.php` 会误报 FAIL（7291 项）——
  路径在 Windows 不存在，脚本回落扫错目录。**必须在容器内跑**，或传 Windows 路径。

### 🔴 最重要的新发现：Valkey 不是「文件层 drop-in」
首次启动**反复重启**，日志：
```
# Can't handle RDB format version 12
# Error reading the RDB base file appendonly.aof.1.base.rdb, AOF loading aborted
```
**原因**：Valkey 从 Redis **7.2.4** 分叉，Redis **7.4** 引入了 RDB v12 + 多段 AOF
目录结构（`appendonlydir/`）。Valkey 8.1 读不了。
→ **Valkey 是 RESP 协议层 drop-in，不是持久化格式层 drop-in。**
→ Redis 7.4 存量数据必须走 `DUMP`/`RESTORE` 或 `--rdb` 导出再导入，**不能挂载旧卷**。
→ 处置：删 `wp004_redis-data` 后重建（本项目该卷只有空缓存，站点根本没在用）。

## 租户越权：定位与实证（只读，未改任何代码/目录/数据库）

### 环境事实（重要，后续操作都依赖）
- **Windows 侧 docker 客户端连不上守护进程**（npipe `dockerDesktopLinuxEngine` 断开），
  但 **WSL Ubuntu 内 docker 正常**。所有容器操作必须走 `wsl -d Ubuntu -- bash -s <<'EOF'` 或 `docker exec`。
- 两个 PHP 开发服务器在抢 8090（都是我起的，收尾漏了）：
  - Windows：`C:\xampp\php\php.exe -S 127.0.0.1:8090 -t public router.php`（PID 30268，20:24:53）
  - WSL：`php -S 0.0.0.0:8090 -t /mnt/d/网站全栈项目/项目004/public .../router.php`（20:39），
    经 `wslrelay.exe`（PID 24552）中继回 Windows → Windows 上 8090 出现两个 LISTENING。
  - 结论：验收结果可能串台，**应停掉 Windows 那个**，保留 WSL 那个。

### 核心结论
租户的**权威来源应落在「租户目录/鉴权服务」（当前不存在）**，
**强制点应落在网关**（唯一全流量必经处，且已有 `authAndTenant` 中间件挂载点），
**数据源侧行级过滤只能做兜底**（已有，但无从判断 tenant 值是否属于调用方）。

### 精确问题定性（修正上一轮的表述）
上一轮记的"编造值即可打通 6 个源"易误导。真·结论：
- **隔离本身有效**：Java `findByTenantId(TenantContext.get())`、Python `filter_by(tenant_id=)` 都按租户过滤行。
  实测 `X-Tenant-Id: acme/t1/zzz-fake` → 200 但返回 `[]`（空，不是别人的数据）。
- **缺的是"身份→租户集合"的绑定**：整条链路（monorepo 全量 Java/Go/Python/TS/SQL 扫描）
  **无任何 tenants 表 / Tenant 实体 / user_tenants 绑定**。
  → `X-Tenant-Id: default` 就能拿到 default 租户 5 条真实订单，而 `default` 是插件默认值、不需要猜。
- 定性：**隔离完全依赖租户 ID 的保密性**，等同于把 ACL 密钥交给客户端。

### 实测矩阵
| 探测 | 结果 |
|---|---|
| `8080/api/orders` 无 Authorization | 401 |
| `8080/api/orders` + `X-Tenant-Id: default` | 200，5 条真实订单 |
| 同上 `acme`/`t1`/`wp004-verify`/`zzz-fake` | 200，`[]` |
| `8000`（ai-python）无租户头 | 400 |
| `8000` 编造租户 | 200 |
| `3001`（node-api）无头 | 200，全量商品（**完全绕过网关，零校验**） |
| `8080/health`、`/ws`、`/api/events/stream` 无鉴权 | 200 / **101** / 200 |

### 三个比"网关不校验"更严重的面
1. **WP 前台对匿名访客泄露**：`includes/class-frontend.php` 的 `render()` / `render_block()` /
   短代码 `[saas_aggregator]` **无任何 capability 检查**；未登录 → `get_current_user_id()=0`
   → 回落 `global.default_tenant='default'` → **匿名访客可见 default 租户的订单/RAG/合规数据**。
   而 REST 路由有 `is_user_logged_in()`（`class-rest.php:183`）——安全边界不一致。
2. **WS/SSE 全租户广播且免鉴权**：`gateway-go/main.go:95` 把 `/health`、`/ws`、`/api/events/stream`
   排除出 `authAndTenant`；`broadcastEvent` 把 `order_created`（含 order_id/status/tenant）
   推给**所有**连接，不按租户分组。未鉴权长连接可收全租户业务事件流。
3. **电商源绕过网关**：`saas-aggregator.php:215` 指向 `http://node-api:3001`，该服务零校验、
   商品无租户维度（当前是公开目录，暂无泄露；按租户分后即全量暴露）。

### 修复思路（分阶段，每阶段可独立验证）
- **阶段 0 止血（改 2 处，零风险）**：`class-frontend.php::render()` 加能力门（与 REST 对齐）；
  `main.go:95` 把 `/ws`、`/api/events/stream` 移出白名单。
  验证：三路径无凭据 → 401；匿名访问短代码页 → 无业务数据。
- **阶段 1 引入绑定（改 1 处）**：`authAndTenant` 内由 Authorization 解出主体 → 查租户目录
  → 校验 X-Tenant-Id 是否在允许集合，否则 403。最小形态用静态映射（env/配置），
  不引入新服务、不改数据库。
- **阶段 2 治理化（可选）**：静态映射换成真正的租户目录表（或复用 WP 用户 meta
  `saas_agg_tenant_id` + REST 查询接口），网关侧带缓存；电商源收口到网关。
- **明确不要做**：在 WP 插件里校验租户合法性 —— 插件只是众多调用方之一，
  在客户端侧做授权校验 = 把 ACL 交给客户端，其它调用方（vue-pc、小程序）仍可绕过。

### 踩坑（工具层面，已解决）
`wsl -d Ubuntu -- bash -lc '...'` **会吞掉单引号**，导致 `-H "Authorization: Bearer x"`
被拆成裸命令报 `Authorization: command not found`；且中文路径赋给 shell 变量后再展开会变空。
**正确写法**：`wsl -d Ubuntu -- bash -s <<'PROBE' ... PROBE`（走 stdin），
中文路径用 `cd` 进入后再用相对路径。

### Ardot MCP 实测硬约束（高价值，下次直接复用）
1. **不支持 SVG 节点导入**：含 `<g>`/`<defs>`/`<style>`/`<linearGradient>` 甚至纯 `<text>+<path>` 的
   SVG 均报 `degenerate geometry: vector is empty (0×0)`。→ 架构图一律用原生 `frame`+`text` 节点手搭。
2. **Insert 不支持 `type:"rect"`**：报 `Unsupported node type: RECT`。→ 矩形框统一用 `type:"frame"`。
3. **`strokes` 的 color 不接受 `a` 字段**：`{r,g,b,a}` 报 `Unrecognized key(s): 'a' at [0].color`。
   → 透明度放 stroke 顶层 `opacity`，color 只给 `{r,g,b}`；并显式给 `strokeWeight:1/1.5`。
4. **z-order = 同父下数组靠后者在上**（类 Figma）。批量建「文本+容器」时务必**先建 frame 再建 text**，
   否则文本会被 frame 的实心填充盖住。本次 14 个 L1/L2 文本节点就是被后建的 frame 盖住，已用 Move 抬到末尾修复。
5. **视觉校验受限**：当前模型 `Read` PNG 返回"不支持图像"；截图 `curl` 落盘被沙箱拒（exit 23），
   改 Python `urllib.request.urlretrieve` 写项目目录。→ 改用 `capture_layout(problemsOnly:true)` 做结构校验
   （可发现溢出/裁剪/越界，但识别不了遮挡，遮挡要靠读根节点的 children 顺序判断）。
6. 可用字体：`Sarasa Gothic SC`（Bold/Semi Bold/Regular）、`Noto Sans SC`。中文统一用 Sarasa Gothic SC。
