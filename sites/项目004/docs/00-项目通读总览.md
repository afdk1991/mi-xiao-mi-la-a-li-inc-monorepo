## 二、架构：三层"不碰"原则

```
浏览器
  │
  ├─ nginx :8091 ──► php-fpm :9000 ──► WordPress 7.0.4 核心（只读共享卷 wp-core）
  │                                      │
  │                                      ├─ 父主题 slstyle      （展示骨架，零改动）
  │                                      ├─ 子主题 slstyle-child（看板模板 + REST 刷新）
  │                                      └─ 插件 saas-aggregator（数据源聚合）
  │                                            ├─ Provider_Manager → 6 个 Provider
  │                                            ├─ API_Client（注入 Authorization + X-Tenant-Id）
  │                                            ├─ Cache（Transients，陈旧回退）
  │                                            ├─ DB（wp_saas_agg_logs 审计表）
  │                                            ├─ Access（统一访问门禁）
  │                                            └─ REST（saas-aggregator/v1，5 条路由）
  │
  ├─► Go 网关 :8080      ← gateway_status / business_core / ai_insights / analytics / compliance
  └─► Node BFF :3001     ← ecommerce（/api/products 不在网关上，实测 8080 返回 404）
```

**三条不可逾越的边界**

1. **核心零改动** —— 三层保证：开发层只用官方扩展机制；校验层 `verify-core.php` 对账 4171 条官方 checksums；部署层核心来自镜像层，宿主机只挂载 `wp-content` + `wp-config.php`。
2. **父主题零改动** —— 所有定制落在子主题，父主题可独立升级。
3. **业务能力不依赖主题** —— 聚合适配全在插件，换主题不丢功能（已用"切回父主题首页仍 200"验证）。

**父主题的两个"自愈"机制**（解决 `after_switch_theme` 对存量站点永不触发的坑）：
- `slstyle_ensure_pages_once()` —— `init`(20)，option `slstyle_pages_version` 守卫，自动补建 about / contact / **user-center**
- `slstyle_ensure_menu_once()` —— `init`(21)，option `slstyle_menu_version` 守卫，自动补齐 `primary` 菜单

**三条开发约定**（2026-08-30 确立）：
1. 禁止硬编码 `page_id`，一律 `slstyle_page_url( $slug )`
2. 分类取数统一 `slstyle_get_primary_categories()`，无分类时区块整段不渲染
3. 必备页面走 `slstyle_required_pages()`，改后必须递增版本号

### 3.3 插件 `saas-aggregator`（43 文件，3,610 行）

**主文件 `saas-aggregator.php`（428 行）**
- PSR-4 风格自动加载器（`SAAS_Agg_*` → `includes/class-*.php`）
- 激活：写默认设置 → 跑 schema 迁移 → `dbDelta` 建表 → 注册每日清理 cron
- 停用：只注销 cron，**保留数据**；卸载：表/option/transient/cron/user_meta 全清
- `saas_agg_bootstrap()` 具名函数 + `did_action`/`doing_action` 兜底（解决"同请求内激活则钩子永不执行"）
- i18n 拆到 `init` 优先级 0（规避 WP 6.7+ "too early" Notice）

**核心类**

| 类 | 职责 |
| --- | --- |
| `SAAS_Agg_Provider_Interface` / `SAAS_Agg_Provider` | 抽象基类：归一化、缓存、错误隔离。`normalize_response()` 兼容三种包装（`items` / `data[]` / `data.{具名集合}`），`unwrap_data_envelope()` 拆 Node 层信封 |
| `SAAS_Agg_Provider_Manager` | 注册与调度中心，`aggregate( $source, $limit )` |
| `SAAS_Agg_API_Client` | HTTP：超时/重试/鉴权头 |
| `SAAS_Agg_Cache` | Transients 封装，**缓存键含租户维度**（防 A/B 租户串读），支持陈旧回退 |
| `SAAS_Agg_DB` | `wp_saas_agg_logs` 审计表，`dbDelta` + 版本存 option；`log()` 脱敏，密钥与响应正文不入库 |
| `SAAS_Agg_Access` | **统一访问门禁**：默认拒绝匿名读真实租户数据；演示模式仅前台豁免 |
| `SAAS_Agg_Tenant` | 用户 → `X-Tenant-Id` 映射（user_meta `saas_agg_tenant_id`） |
| `SAAS_Agg_REST` | 5 条路由 |
| `SAAS_Agg_Settings` | 后台「设置 → SaaS 聚合器」 |
| `SAAS_Agg_Frontend` | 短代码 `[saas_aggregator source limit]` + 区块服务端渲染 |

**6 个数据源（实测归属，勿凭直觉改）**

| ID | 名称 | 层 | 服务 | 路径 | 方法 | TTL |
| --- | --- | --- | --- | --- | --- | --- |
| `gateway_status` | 网关状态 | 接入层 Go | gateway-go:8080 | `/api/gateway/status` | GET | 120s |
| `business_core` | 业务核心 | 应用层 Java | gateway-go:8080 | `/api/orders` | GET | 300s |
| `ai_insights` | AI 洞察 | 智能层 Python | ai-python:8000 | `/api/ai/rag` | **POST** | 600s |
| `analytics` | 决策分析 | 数据层 | ai-python:8000 | `/api/analytics/dashboard` | GET | 900s |
| `compliance` | 合规审计 | 安全合规层 | ai-python:8000 | `/api/compliance/status` | GET | 600s |
| `ecommerce` | 电商商品 | 电商层 Node | **node-api:3001** | `/api/products` | GET | 180s |

**REST 路由（`saas-aggregator/v1`）**

| 路由 | 方法 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/sources` | GET | 登录 + 限流 | 数据源清单与配置状态 |
| `/data` | GET | 登录 + 限流 | 聚合数据，支持 `source` / `limit` / `fresh` |
| `/health` | GET | 登录 + 限流 | 健康探针，有源故障返回 503 |
| `/cache/flush` | POST | `manage_options` | 清缓存 |
| `/logs` | GET | `manage_options` | 审计日志（按租户/源/结果筛选） |

限流：每 IP 每分钟 60 次（Transients 计数，过滤器可调）。

**数据库**

- 核心 12 张表 + 唯一自建表 `wp_saas_agg_logs`（11 字段，3 个索引：租户 / 数据源 / 时间）
- 建表四要素：`$wpdb->prefix` + `get_charset_collate()` + `dbDelta()` + 版本存 option
- WP-Cron `saas_agg_prune_logs` 每日清理，默认保留 30 天

**开放钩子**：`saas_agg_providers`、`saas_agg_public_read`、`saas_agg_rest_public_read`、`saas_agg_rest_rate_limit`、`saas_agg_view_capability`、`saas_agg_log_retention_days`

### 已全部闭环（2026-08-30）

| 原问题 | 修法 |
| --- | --- |
| P1 `page_id=14` 三处死链（那是 nav_menu_item 的 ID，不是页面） | `slstyle_page_url()` 按 slug 解析 + 验收脚本加"禁硬编码 page_id"断言 |

| P2 商标残留 "参考 Zibll 设计风格" | 更名 `slStyle` + 清除 11 处表述，全项目 grep 命中 0 |

| 🟢 `primary` 菜单注册了却从未渲染 | header 改 `wp_nav_menu('primary')` + `SLStyle_Nav_Walker` |

### 仍然开放

| 级别 | 事项 |
| --- | --- |
| 🟡 | **网关侧租户绑定 phase-1** —— Go 源码已改（`main.go.bak-20260830`），WSL 无 go 工具链未编译；最终需接入 IdP 做"主体→租户归属"裁决 |
| 🟡 | 与微服务栈的**读写边界**（目前纯只读）—— 是否要写回？幂等与重试策略？ |
| 🟢 | `mixmlaal-wp-portal:8088` 是替换还是并存？ |
| 🟢 | Valkey 容器已起但**未启用对象缓存**；容器内无 MTA，邮件会静默失败 |
| 🟢 | 对外分发需补 3 份许可文本：Nyholm/Psr7 的 MIT、php-http/discovery 的 MIT、OFL 1.1（9 个字体族） |
| ⚠️ | 根目录无 `.gitignore`，`.env` 有入库风险 |

### 合规结论

**有条件商用**。GPLv2 不限制"运行"，SaaS 模式零开源义务；打包分发才触发 GPLv2 六项义务（最常被漏的是"标注修改说明"）。HTTP 调用下游微服务属 mere aggregation，不传染。Redis 7.4 许可风险已通过换 **Valkey（BSD-3）** 消除；Akismet 未激活无 Key，风险 0。

> ⚠️ Valkey 从 Redis 7.2.4 分叉，**读不了 Redis 7.4 的 RDB v12** —— 协议层 drop-in，不是持久化格式层 drop-in。
