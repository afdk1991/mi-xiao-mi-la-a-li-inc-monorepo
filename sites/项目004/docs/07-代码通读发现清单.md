## 3. 本轮新发现的问题（按严重度）

### ✅ P1 · `page_id=14` 硬编码指向菜单项，前台 404 —— **已于 2026-08-30 修复闭环**

**位置**
- `themes/slstyle/front-page.php:57` —— 「查看完整演示 ›」
- `themes/slstyle/header.php:32` —— 「业务监控」
- `themes/slstyle/header.php:34` —— 「SaaS 聚合演示」

**实测**
```
GET /?page_id=14   →  HTTP/1.1 404 Not Found
GET /?page_id=4    →  301 → /dashboard/            → 200
GET /?page_id=5    →  301 → /aggregator-shortcode/ → 200
```

**根因**：`14` 是 `wp_posts` 中 `post_type='nav_menu_item'` 的记录 ID，不是页面 ID。
真实演示页是 `dashboard`(ID=4) 与 `aggregator-shortcode`(ID=5)。

**影响**：首页 Hero 区的「查看完整演示」、全站 header 的「业务监控」下拉两项，
共 3 处链接全部 404。且因 header 是全站共用，**每个页面都受影响**。

**修复方向**：硬编码 ID 本身就是反模式。应改为按 `post_name` 查询
（`get_page_by_path('dashboard')`），或固化到主题 mod / 菜单里走 `wp_nav_menu()`。

**✅ 修复记录（2026-08-30）**

新增 `slstyle_page_url( $slug, $fallback = '' )`（`functions.php`），按 slug 解析页面链接，
页面缺失时回落到站内首页，**从机制上保证导航永不产出 404**。

| 位置 | 改前 | 改后 |
|---|---|---|
| `front-page.php:57` | `home_url('/?page_id=14')` | `slstyle_page_url('dashboard')` |
| `header.php:32` | 同上 | `slstyle_page_url('dashboard')` |
| `header.php:34` | 同上 | `slstyle_page_url('aggregator-shortcode')` |

顺带修了两处关联问题：
- 下拉项新增「数据看板」，原三选一变成「数据看板 / SaaS 聚合演示 / 统一监控门户」三项。
- `slstyle_build_primary_menu()` 的演示中心引用了**根本不存在的** slug `saas-aggregator-demo`，
  改为 `dashboard` / `aggregator-shortcode` / `sample-page`。

**回归防线**：`scripts/verify-site.php` 新增断言「模板无硬编码 page_id」，
扫描父主题全部 `*.php` 匹配 `page_id=\d+`，一旦有人再写死 ID 立即 FAIL。

  → 主导航**不生成**「用户中心」菜单项
- 实测菜单结构：首页 / 文章中心(>未分类) / 关于我们(>联系我们) / 演示中心(>1项)

**✅ 修复记录（2026-08-30）**

**实测结果**：页面已自动建出 `ID=15 / post_name=user-center / _wp_page_template=user-center.php`，
`slstyle_pages_version=2`。前台 `GET /user-center/` → 200，
body class 确认 `page-template-user-center-php page-id-15`。

同时在 header 硬编码导航补上「用户中心」入口（此前该入口依赖 WP 菜单，而菜单构建
只在切换主题时执行，存量站点永远等不到）。

**回归防线**：`verify-site.php` 新增两条断言 ——
「主题必备页面齐全」（about / contact / user-center）、「用户中心模板已绑定」。

### ✅ P2 · header 硬编码 4 个分类名，库中不存在 —— **已于 2026-08-30 修复闭环**

若该键未被填充会触发 PHP undefined index 警告。

**修复方向**：改为动态取分类（`get_categories(array('hide_empty'=>true,'parent'=>0))`），

**✅ 修复记录（2026-08-30）**

取顶级分类、排除默认「未分类」、按文章数降序。header 与 front-page 共用，避免两处口径漂移。

- `header.php` 下拉菜单改为 `foreach` 渲染真实分类；无分类时不渲染子菜单，
  父项链接改用 `get_post_type_archive_link('post')`（语义正确，而非回落首页）。
- `front-page.php` 分类卡片区（原 6 段重复 HTML + 硬编码中文名）重写为循环渲染：
  配色与 SVG 图标放进 `$card_styles` 视觉池按索引轮换，**任意数量的分类都有一致外观**；
  描述优先取分类自身 `description`，为空则显示「共 N 篇文章」。
- **整段 `if ( $cat_cards )` 守卫**：库里没有可展示分类时该 section 不渲染，
  彻底消除死链与 undefined index 风险。

⚠️ **需要你决定**：当前库里只有「未分类」，所以首页分类卡片区**暂时不显示**。
这是刻意设计（宁缺勿造死链）。想让它出现就去后台建几个分类即可，无需改代码。

### ✅ P2 · i18n 文本域加载过早（WP 6.7+ Notice）—— **已于 2026-08-30 修复闭环**

**位置**：`saas-aggregator.php:365` 在 `saas_agg_bootstrap()` 内调用
`load_plugin_textdomain()`，而 `saas_agg_bootstrap()` 挂在 `plugins_loaded`（优先级 10）。

**实测日志**（`wp-content/debug.log`）
```
PHP Notice: Function _load_textdomain_just_in_time was called incorrectly.
Translation loading for the <code>saas-aggregator</code> domain was triggered too early.
Translations should be loaded at the <code>init</code> action or later.
```

**根因**：`register_activation_hook` 内调用的 `saas_agg_get_default_settings()`
使用了 `__()`，早于 `init`，触发 WP 6.7 的 just-in-time 文本域检查。

**影响**：仅 debug 开启时刷日志，功能无碍。但会被插件目录审查（wp.org / 企业内审）判为不合规项。

**修复方向**：把 `load_plugin_textdomain()` 从 `saas_agg_bootstrap()` 拆出，
单独挂 `init`（优先级 0）。

**✅ 修复记录（2026-08-30）**

从 `saas_agg_bootstrap()` 拆出独立函数 `saas_agg_load_textdomain()`：

```php
add_action( 'init', 'saas_agg_load_textdomain', 0 );
// 请求中途激活 / CLI 引导时 init 已过，补加载一次
if ( did_action( 'init' ) || doing_action( 'init' ) ) {
    saas_agg_load_textdomain();
}
```

保留了原有的「请求中途被 `activate_plugin()` 激活」兜底逻辑，函数内用 `static $loaded` 保证幂等。

**实测验证**（关键，不是靠推断）：修复前记录日志行数 → 连续触发 7 次请求
（首页 ×3、用户中心 ×3、REST ×1）→ 日志行数 **27 → 27，新增 0 行**。
`init` 钩子上确认已挂载 `saas_agg_load_textdomain`。

## 7. 第 8 轮补充（2026-08-30）：收尾与一处关键修复

本轮目标：把上一轮遗留的 3 个待决项全部闭环，并补齐工具/内容，最终跑通全量回归。

### 7.1 🔴 关键修复：front-page.php 分类段被压成单行导致首页 500

**现象**：curl 首页拿到 200 的 `zibstyle` 旧页面，但带 `no-cache` 的请求直接 500。
debug.log 报错：`Uncaught TypeError: count(): Argument #1 ($value) must be of type
Countable|array, null given in front-page.php:70`，根因 `Undefined variable $card_styles`。

**根因**：上一轮「继续推进」重写分类卡片时，Edit 把整段代码压成了**单行**，
`$card_styles` 定义前的 `//` 注释把同行后续代码全部注释掉，使 `$card_styles` 未定义、
`count()` 直接 fatal。该错误自 8/29 17:13 起一直存在，**首页实际持续 500**；
此前 curl 看到的 `zibstyle` 页面是陈旧缓存页（容器无页面缓存插件，属 fasctcgi 上游
对同一请求的偶发旧响应/浏览器层缓存假象，并非真实渲染）。

**修复**：用脚本把整段重写为规范多行，且 `$card_styles` 在 `if ( $cat_cards )` 守卫**之外**
无条件先定义，彻底消除"未定义变量"。`php -l` 通过。验证：首页 HTTP 200、body class
`wp-theme-slstyle`、4 张 `cat-card` 正常渲染、无任何 `page_id=14` 泄漏。

> 教训：WP 模板里用 `//` 行注释的片段绝不能压成单行；后续批量 Edit 后必须 `php -l` + 实拉首页。
